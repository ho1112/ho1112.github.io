## 🔥 이번 주 핵심 테마

이번 주는 "JavaScript로 만들던 것을 플랫폼에 맡긴다"는 흐름이 곳곳에서 보였습니다. React Aria의 Sheet는 CSS scroll snap과 view timeline만으로 스와이프 제스처를 구현했고, CSS Anchor Positioning은 툴팁 위치 계산을 JS에서 걷어냅니다. 한편 Next.js 16.4는 Cache Components를 공식 권장 모델로 올리며 에이전트 기반 업그레이드 도구를 내놓았고, Smashing은 디자인 시스템을 AI가 읽을 수 있게 만드는 방법을 다뤘습니다. Remix 3.0의 탈React와 Deno의 Cloudflare 합류처럼 프레임워크와 런타임 지형이 재편되는 소식도 이어졌습니다.

## 1. 🔍 심층 분석
- **[React Aria's New Swipeable Sheet and the CSS Tricks Behind It](https://react-aria.adobe.com/blog/sheet)** (출처: *React Status #493*)
   - 배경: 바텀 시트 같은 스와이프 오버레이는 보통 JS 터치 이벤트로 구현해 왔습니다. React Aria 팀은 이를 걷어내고 스크롤 자체를 제스처 엔진으로 쓰는 방식을 택했습니다.
   - 핵심 기능: 뷰포트 높이의 2배인 스크롤 컨테이너 안에 시트를 두고, 열림과 닫힘 위치에 scroll snap 지점을 둡니다. 스와이프 진행도에 맞춘 애니메이션은 `view-timeline`으로 연결하고, 부분적으로 열리는 snap points는 1px 마커 요소와 `scroll-margin-top: 100dvh`로 구현합니다. 시트 스택은 `timeline-scope`와 `animation-composition: accumulate`로 처리합니다.
   - 코드 예제:
```css
     .sheet {
       view-timeline: --sheet;
       view-timeline-inset: 0 100dvh;
     }
     .backdrop { animation-timeline: --sheet; animation-range: entry; }
```
   - 실무 적용: 스와이프가 메인 스레드 밖에서 디스플레이 주사율로 동작하고, 네이티브 모멘텀과 러버밴딩 물리가 공짜로 따라옵니다. `position`, `swipeDirection`, `snapPoints`, `preventDismissal` 같은 props로 방향과 동작을 조절할 수 있습니다.
   - 주의사항: iOS 소프트웨어 키보드는 동적 뷰포트 단위가 반응하지 않아, 콘텐츠에 `padding-bottom: calc(100dvh - var(--visual-viewport-height))`를 따로 줘야 합니다.
- **[Next.js 16.4 Makes Cache Components the Recommended Default](https://nextjs.org/blog/next-16-4)** (출처: *React Status #493*)
   - 배경: 16.x 동안 App Router의 암묵적 캐싱을 대체할 Cache Components 모델이 발전해 왔습니다. 일부 케이스에서 기존 모델과 같은 비용·성능 보장이 어려워 보편적으로 권하지 못했는데, 16.4에서 그 간극이 메워졌습니다.
   - 핵심 기능: `'use cache'`는 컴포넌트 단위의 Cache-Control에 해당하며, 한 페이지 안에서 정적 셸과 요청 시점 렌더링을 섞을 수 있습니다. 16.4에는 라우트의 셸·프리페치·네비게이션이 정적임을 보장하는 `ensureStatic`과, 프리페치에서 캐시 콘텐츠를 제외하는 `navigation()`·`prefetch()`가 추가되었습니다.
   - 코드 예제:
```jsx
     async function Projects({ userId }) {
       'use cache';
       cacheLife('hours');
       // DB 조회 후 렌더링
     }
```
   - 실무 적용: `create-next-app`으로 만든 새 앱은 Cache Components가 기본 활성화됩니다. 기존 앱은 `npx next@canary upgrade --agent=latest`로 에이전트용 마이그레이션 가이드와 codemod를 받을 수 있습니다. 개발 환경에서는 Turbopack 디스크 캐시가 20~25% 줄고 React 19.3도 포함됩니다.
   - 주의사항: Cache Components는 Next.js 17에서 기본이 될 예정입니다. 에이전트 피드백, Rust React Compiler 같은 일부 기능은 아직 experimental 플래그 뒤에 있습니다.

## 3. 📝 추천 아티클 & 팁
- **[CSS Does Your Tooltip Positioning Now](https://allthingssmitty.com/2026/10/05/css-does-your-tooltip-positioning-now/)** (출처: *Frontend Focus #761*)
  + 배경: 툴팁이나 팝오버 위치를 `getBoundingClientRect()`로 계산하면 창 크기 변경, 스크롤, 뷰포트 하단 넘침마다 리스너와 보정 로직이 필요했습니다.
  + 핵심 인사이트: `anchor-name`과 `position-anchor`로 두 요소를 연결하면 브라우저가 위치를 계속 재계산합니다. `position-try-fallbacks`는 넘칠 때 반대편으로 뒤집고, `popover` 속성과 함께 쓰면 JS 없이 드롭다운이 됩니다. `anchor-size(width)`로 드롭다운 너비를 버튼에 맞출 수도 있습니다.
  + 코드 예시:
```css
    .term { anchor-name: --my-anchor; }
    .note {
      position: fixed;
      position-anchor: --my-anchor;
      position-area: bottom;
      position-try-fallbacks: flip-block, flip-inline;
    }
```
  + 왜 유익한가: 위치 문제와 표시 시점 문제를 구분해 줍니다. anchor positioning은 "어디에" 놓을지만 해결하고, 언제 보일지는 `:has()`나 popover가 맡습니다. 앵커 관계는 시각적일 뿐이라 스크린 리더에는 도움이 되지 않으므로 접근성 기능으로 착각하지 말라는 경고도 실무에서 중요합니다.
- **[Why Don't More Developers 'Use the Platform'?](https://nolanlawson.com/2026/10/03/why-dont-more-developers-use-the-platform/)** (출처: *JavaScript Weekly #805*)
  + 배경: 플랫폼 옹호 진영에 있던 Nolan Lawson이 일부러 반대편에서 "왜 사람들은 브라우저 기능을 두고 직접 만드는가"를 분석합니다. [Hacker News에서도 긴 토론](https://news.ycombinator.com/item?id=49950554)이 벌어졌습니다.
  + 핵심 인사이트: 이유로는 브라우저가 생태계를 따라가던 역사, npm 라이브러리가 주는 친숙함과 문서화, CSS의 난해함이 꼽힙니다. 그보다 직접 만드는 것이 더 재미있고 IKEA 효과까지 있다는 점이 핵심입니다. 모달을 직접 만들며 포커스 트랩까지 배우는 과정이 학습이 된다는 것입니다. AI 코딩이 이를 줄일지 늘릴지에 대해서는 낙관과 비관 두 시나리오를 모두 제시합니다.
  + 왜 유익한가: 동료나 팀의 "직접 구현" 성향을 비난 대신 이해하는 관점을 줍니다. 본인의 ClickHouse 압축 경험담이 플랫폼에 맡기는 편이 낫다는 사례로 설득력 있습니다.
- **[Expose Your Design System To AI](https://www.smashingmagazine.com/2026/06/how-make-design-system-ai-ready/)** (출처: *Smashing Newsletter #579*)
  ![How To Make Your Design System AI-Ready](https://mcusercontent.com/16b832d9ad4b28edf261f34df/images/2692e8dd-ee96-5341-e05a-735c498ad834.png)
  + 배경: AI는 일관된 결과를 내려면 명확한 결정과 원칙이 필요합니다. 사람은 경험으로 빈틈을 메우지만 AI는 추측으로 채우기 때문입니다.
  + 핵심 인사이트: Vitaly Friedman의 가이드는 디자인 시스템을 AI-ready로 만드는 팁, 도구, 사례를 담고 있습니다. 드리프트를 줄이고 컨텍스트를 유지하는 방법은 Hardik Pandya의 [LLM이 소비할 수 있는 형식으로 재구성하는 방법](https://hvpandya.com/llm-design-systems)에서 더 볼 수 있습니다.
  + 왜 유익한가: 디자인 시스템을 사람용 문서에서 기계가 읽는 명세로 확장하는 방향을 구체적인 자료와 함께 보여 줍니다.

  + 업데이트: 다시 만든 풀스택 프레임워크의 안정 버전으로, React가 필요 없습니다. 공식 글은 아직 없고 [RC 릴리스 글](https://remix.run/blog/remix-3-release-candidate)에 더 많은 정보가 있습니다.
- **[Preact 11 Released](https://preactjs.com/blog/preact-11/)** (*JavaScript Weekly #805*)
  + 업데이트: 6년 만의 새 메이저 버전으로 개선된 hydration, 자동 ref forwarding, ESM 전용 패키지가 핵심입니다. [업그레이드 가이드](https://preactjs.com/guide/v11/upgrade-guide/)가 있습니다.
- **[Nuxt 4.6: A Big Step Towards a Server-Agnostic Nuxt](https://nuxt.com/blog/v4-6)** (*JavaScript Weekly #805*)

- **[Effect 4.0: A Smaller Core, Rebuilt Runtime](https://effect.website/blog/releases/effect/40)** (*JavaScript Weekly #805*)
  + 업데이트: 리소스 관리, 동시성, 재시도, 타입 있는 에러를 다루는 라이브러리를 밑바닥부터 다시 썼습니다. 최소 번들이 5배 작아지고 동시 태스크당 메모리 사용량이 86% 줄었다고 합니다.

- **[Redux Toolkit 2.13: TypeScript 7 Support and a Steadier useQuery](https://github.com/reduxjs/redux-toolkit/releases/tag/v2.13.0)** (*React Status #493*)

## ✍️ 마치며
이번 주 소식을 읽으면서 "직접 만드는 즐거움"과 "플랫폼에 맡기는 효율" 사이의 균형을 다시 생각했습니다. React Aria가 스크롤과 view timeline만으로 시트를 구현한 사례는 플랫폼 기능이 충분히 성숙했음을 보여 줍니다. 반면 Nolan Lawson의 지적처럼, AI 에이전트가 코드를 쓰는 시대에는 플랫폼에 맡길 것인지 판단하는 일이 점점 개발자의 몫이 됩니다. Next.js의 에이전트용 업그레이드 도구와 AI-ready 디자인 시스템 논의도 같은 방향이었습니다. 도구가 코드를 쓰는 속도가 빨라질수록 명확한 계약과 가드레일을 설계하는 능력이 더 중요해진다고 생각합니다.
