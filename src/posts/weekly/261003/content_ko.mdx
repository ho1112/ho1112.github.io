## 🔥 이번 주 핵심 테마
이번 주는 "프론트엔드 성능과 구조의 재점검"이 중심이었습니다. GitHub는 CSS-in-JS를 걷어내고 CSS Modules로 옮겨 SSR 시간을 크게 줄였고, Anthropic은 Claude 웹 앱의 time-to-typeable을 3.1초에서 0.55초로 단축한 과정을 공개했습니다. 과도한 추상화가 개발자와 AI 에이전트 모두에게 비용이 된다는 측정 결과도 나왔습니다. 한편 Vite+ 1.0, Cloudflare의 cf CLI, EmDash 1.0 등 도구 생태계도 빠르게 움직이고 있습니다.

## 1. 🔍 심층 분석
- **[Improving Site Performance by Shipping More CSS](https://github.blog/engineering/architecture-optimization/improving-site-performance-by-shipping-more-css/)** (출처: *Frontend Focus #760*)
  ![Improving Site Performance by Shipping More CSS 대표 이미지](https://res.cloudinary.com/cpress/image/upload/w_1280,e_sharpen:60,q_auto/wqdeehcjo7y0imo6gazv.jpg)
  - 배경: GitHub는 3년에 걸쳐 github.com에서 styled-components와 CSS-in-JS를 걷어내고 CSS Modules로 전환했습니다.
  - 핵심 기능: CSS는 오히려 더 많이 배포하게 되었지만, 서버 사이드 렌더링 시간이 55% 줄었다고 보고합니다. CSS Modules는 브라우저 표준이 아니라 번들러 관례로, `.module.css` 파일의 클래스를 고유한 이름으로 재작성해 파일 단위로 스타일을 격리하며 런타임 비용이 없습니다.
  - 실무 적용: CSS-in-JS 런타임이 SSR 성능에 부담이 되는 서비스에서 마이그레이션을 검토할 근거로 쓸 수 있습니다. 같은 글이 JavaScript Weekly #804에도 소개되었습니다.
  - 주의사항: 3년이 걸린 대규모 전환이라는 점에서 점진적 이전 전략이 필요합니다. 세부 한계는 원문 확인이 필요합니다.
- **[The Grand Unifying Architecture of Frontend](https://dev.to/playfulprogramming/the-grand-unifying-architecture-of-frontend-bhk)** (출처: *JavaScript Weekly #804*)
  ![The Grand Unifying Architecture of Frontend 대표 이미지](https://res.cloudinary.com/cpress/image/upload/w_1280,e_sharpen:60,q_auto/q97l6jlstbu4nz3us8ex.jpg)
  - 배경: HTMX, React, LiveView 등 프레임워크가 제각각으로 보이는 이유를 하나의 관점으로 설명하려는 글입니다.
  - 핵심 기능: SolidJS 창시자 Ryan Carniato는 이 도구들이 내비게이션, 콘텐츠, 즉각적인 UI 피드백이라는 세 가지 일을 클라이언트와 서버 사이에서 나누는 방식만 다르다고 주장합니다. 이어서 Solid 2.0이 이 스펙트럼 전체를 다루려 한다고 설명합니다.
  - 실무 적용: 프레임워크를 고를 때 기능 목록 대신 이 세 가지 책임이 어디에 놓이는지를 기준으로 비교해 볼 수 있습니다.
  - 주의사항: Solid 2.0 관련 내용은 저자가 자기 프레임워크를 설명하는 관점이라는 점을 감안해야 합니다.

## ✍️ 마치며
이번 주 소식을 한 줄로 요약하면 "측정하고 걷어낸다"입니다. GitHub의 CSS Modules 전환과 Claude 웹 앱의 성능 개선 모두 눈에 띄는 신기술이 아니라 병목을 측정해 불필요한 계층을 제거한 사례였습니다. 추상화 비용이 AI 에이전트 비용으로도 나타난다는 측정 결과는, 코드의 독자가 사람에서 에이전트로 넓어지고 있음을 보여 줍니다. 가상화 훅 하나로 INP를 1,256ms에서 96ms로 낮춘 사례도 같은 맥락이어서, 복잡한 해법보다 먼저 렌더링 대상을 줄일 수 있는지 살펴보는 습관이 유효하다고 생각합니다. 어린이 대상 디자인처럼 사용자를 설계 과정에 직접 참여시키는 접근은 성능 최적화와 달라 보여도, 실제 사용 맥락에서 출발한다는 점에서 맞닿아 있다고 느꼈습니다.
