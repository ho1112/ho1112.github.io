## 🔥 今週の主要テーマ
今週は「速度」と「明示性」がキーワードでした。TanStack Start 1.0が正式リリースされてReactメタフレームワークの選択肢が広がり、CloudflareとVoidZeroはTypeScriptをRustに移植したtsrsを公開して、型チェック速度の競争に火をつけました。ブラウザ側では、ネイティブJSONモジュール、JPEG XLの全面サポート、Interop 2027の投票がプラットフォームの進化を示しています。一方、Next.jsとPHPの重大なRCEパッチのニュースは、アップデートを先延ばしにしないようにという警告でもあります。

## 1. 🔍 深掘り
- **[TanStack Start Reaches 1.0](https://tanstack.com/blog/tanstack-start-1-0)** (出典: *React Status #494*)
  ![TanStack Start Reaches 1.0](https://res.cloudinary.com/cpress/image/upload/w_1280,e_sharpen:60,q_auto/ejihjkazanj4b02abevr.jpg)
   - 背景: Startは、型安全なルーター(TanStack Router)を作る過程で自然にフルスタックへ拡張されたフレームワークです。2026年10月13日の1.0正式リリースでRC段階という但し書きが外れ、作者のTanner LinsleyはAPIを公式に維持していくと約束しました。
   - 主な機能: ルート単位で、サーバーレンダリング、サーバーでのデータロードのみ、クライアントレンダリングを選択できます。型付きのサーバー関数や、クライアントとサーバーを行き来するミドルウェアも提供しており、サーバーとクライアントの実装を一か所に並べて書ける`createIsomorphicFn`が代表的な明示的APIです。
   - コード例:
     ```tsx
     const getOrigin = createIsomorphicFn()
       .server(() => new URL(getRequest().url).origin)
       .client(() => window.location.origin)
     ```
   - 実務での活用: 従来のSPA方式の状態管理やクライアントナビゲーションを維持しつつ、必要な箇所だけサーバーを使いたいときに便利です。公式ガイドはNext.jsやRCからのマイグレーションドキュメントを提供しており、ニュースレターは同じアプリをNext.js 16.4と比較したサードパーティのベンチマーク(動的リクエストのスループット2.9〜8.6倍、ビルド約1.7倍)も紹介しています。
   - 注意事項: RSCのサポートはStartのコアモデルとは切り離されたオプトイン方式です。作者はtanstack.comではRSCを使っていたものの再び取り除いたと明かしており、npmで1.0が`1.169`と表記される点も知っておくとよいでしょう。
- **[tsrs: Cloudflare and VoidZero's Rust Port of TypeScript](https://blog.cloudflare.com/typescript-rust-port/)** (出典: *JavaScript Weekly #807*)
   - 背景: Goに移植されたTypeScript 7はすでに高速ですが、RustにはWasm環境でガベージコレクターなしにメモリを効率的に扱えるという利点があります。Cloudflareは、フォークではなくTypeScriptチームと協力する忠実なポートであることを強調しています。
   - 主な機能: 同じ型チェックのワーカー数で比べると、TypeScript 7.0より最大8倍速く、メモリ使用量は約70%少ないとのことです。Oxcツールチェーンの中でインキュベートされており、WebAssemblyでも動作します。
   - コード例:
     ```bash
     npm install tsrs
     npx tsrs
     ```
   - 実務での活用: Oxlintの型認識リントルールのような統合が予告されており、ブラウザやWorkersのようなサンドボックス上で開発ツールチェーンを最後まで動かすシナリオが開けます。ニュースレターは、Owner.comが社内の型チェックを80秒から7秒に短縮した事例も紹介しています。
   - 注意事項: まだ実験的なリリースで、診断メッセージの出力順序など、アップストリームとの差異が残っています。TypeScript 7.1ベータも7.0比で最大2.5倍高速化したとのことなので、比較計測が必要です。

## 2. 🛠️ ツール & ライブラリ
- **[TanStack Hotkeys Beta: A Type-Safe Library for Keyboard Shortcuts](https://tanstack.com/hotkeys/latest)** (出典: *React Status #494*)
  + 概要: keydownリスナーでショートカットを実装すると、入力フィールド、Mac/Windowsの修飾キー、異なるキーボード配列、IME入力といった例外処理がどんどん積み重なります。Hotkeysは、こうしたクロスプラットフォームのエッジケースを、フレームワーク非依存のコアとReact、Vue、Solidなどのアダプターで整理したベータ版ライブラリです。
  + 使い方:
    ```tsx
    useHotkey('Mod+S', save)
    ```

- **[Pixel: Build Graphical Applications in the Terminal](https://pixelgui.com/)** (出典: *React Status #494*)
  ![Pixel demo: graphical React apps running in a terminal](https://res.cloudinary.com/cpress/image/upload/w_1280,e_sharpen:60,q_auto/nishfkuexsqapfi2rcgp.jpg)
  + 概要: InkのようにReactでターミナルアプリを作りつつ、角丸、グラデーション、フォントといったピクセル単位のグラフィックを描画できるレンダラーです。Chromium WebViewコンポーネントまで内蔵しており、Webアプリをターミナルウィンドウに表示することもできます。
  + 使い方:

  + 実践チップ: Ghostty、iTerm2、WezTermなど、対応ターミナルを先に確認してください。macOSとLinuxをサポートしており、WindowsはまだWSL経由でのみ利用できます。

## 3. 📝 おすすめ記事 & チップ
- **[Native JSON Modules](https://allthingssmitty.com/2026/03/16/native-json-modules-are-finally-real/)** (出典: *Smashing Newsletter #581*)
  ![Native JSON Modules](https://mcusercontent.com/16b832d9ad4b28edf261f34df/images/20c7f37d-0d28-547a-9dc8-f931776d6f2b.png)
  + 背景: `import config from "./config.json"`はネイティブのように見えますが、実際にはバンドラーがビルド時にJSONをモジュールに変換していたものでした。import attributesのおかげで、今はランタイムがJSONモジュールを直接処理します。
  + 主なインサイト: `with { type: "json" }`は「このファイルは実行せず、JSONとしてパースせよ」という明示的な契約です。パースされたオブジェクトは通常のESモジュールと同様に一度だけ評価されキャッシュされるため、2回importしても同じオブジェクトです。一方、バンドラーとは異なり、デフォルトではバンドルにインライン化されません。
  + コード例:
    ```js
    import config from "./config.json" with { type: "json" };
    const mod = await import("./config.json", { with: { type: "json" } });
    ```
  + 参考になるポイント: バンドラーなしで純粋なESMのままJSONを使えるという点だけでなく、同じパターンがCSSモジュールスクリプトなどへ広がっていくという大きな見取り図を示してくれます。ブラウザではサーバーが`Content-Type: application/json`を返す必要があり、CORSのルールがそのまま適用されるという実務上の注意点にも触れています。
- **[Josh Comeau's The Future of CSS](https://www.joshwcomeau.com/css/interop-2027/)** (出典: *Frontend Focus #763*)
  + 背景: ブラウザベンダーが協力するInteropプロジェクトは、2027年の優先事項を決めるために提案のランキング投票を開き、多くの開発者が自分の順位を共有しています。Joshの記事は、その中の上位10件を、実際のデモとブラウザのサポート状況とともに紹介しています。
  + 主なインサイト: CSS関数、`corner-shape`、`border-shape`、アンカー付きコンテナクエリ、スクロールトリガーアニメーション、`reading-flow`、ギャップ装飾、スクロール状態コンテナクエリなどが候補です。執筆時点ではほとんどがChrome 155とEdge 154のみのサポートで、FirefoxとSafariは未サポートですが、プログレッシブエンハンスメントで今日から使えるものも多くあります。
  + コード例:
    ```css
    .grid {
      display: grid;
      reading-flow: grid-rows;
    }
    ```
  + 参考になるポイント: レスポンシブレイアウトで視覚的な順序とタブ順序がずれるアクセシビリティの問題を`reading-flow`一行で解決する方法のように、すぐに使えるチップがたくさんあります。ニュースレターは、約10件の提案に投票するとFirefoxチームにとって有益なフィードバックになると紹介しています。
- **[JPEG XL vs AVIF for Web Use-Cases](https://jakearchibald.com/2026/jpeg-xl-vs-avif/)** (出典: *Frontend Focus #763*)
  ![JPEG XL vs AVIF for Web Use-Cases](https://res.cloudinary.com/cpress/image/upload/w_1280,e_sharpen:60,q_auto/v1792585763/nrxh8gwtp2lom2spe99p.png)
  + 背景: JPEG XLがすべての主要ブラウザに入り、Firefox 158がデフォルト有効化に加わった最新のブラウザとして紹介されました。
  + 主なインサイト: Jake ArchibaldがJPEG XLをAVIFとWebのユースケース基準でベンチマークし、詳細な比較と実務的な結論をまとめました。
  + 参考になるポイント: 画像フォーマットの切り替えを検討する際に、エンコード品質や用途別の違いを一度に確認できる長文の比較記事です。

## ✍️ おわりに
今週のニュースを貫く問いは、「ツールが速くなると何が変わるのか」だったように思います。tsrsやTypeScript 7.1が示すように、型チェックが数倍速くなれば、型を厳密に書くコストが下がります。TanStack Start 1.0の型安全性と明示的なAPIがエージェント時代にいっそう力を発揮するという作者の見方も、結局は同じ文脈で読み取れます。

反対に、Next.jsとPHPのRCEパッチは、速度や利便性の裏にある負担を思い出させてくれます。フレームワークを選ぶ際には、パフォーマンスの数値と同じくらい、アップデートへの対応体制や攻撃対象領域も併せて見る必要があると感じます。Webプラットフォームが、JSONモジュールやCSSの機能でバンドラーの役割を吸収していく流れも、同じ方向に見えます。ビルド段階で行っていたことがランタイムや言語標準へ移っていくほど、私たちが知っておくべきことはツールの使い方よりも、プラットフォーム自体の動作になっていきます。
