## 🔥 이번 주 핵심 테마
이번 주는 "속도"와 "명시성"이 키워드였습니다. TanStack Start 1.0이 정식 출시되며 React 메타프레임워크의 선택지가 넓어졌고, Cloudflare와 VoidZero는 TypeScript를 Rust로 옮긴 tsrs를 공개해 타입 체크 속도 경쟁에 불을 붙였습니다. 브라우저 쪽에서는 네이티브 JSON 모듈, JPEG XL 전면 지원, Interop 2027 투표가 플랫폼의 진화를 보여줍니다. 한편 Next.js와 PHP의 치명적인 RCE 패치 소식은 업데이트를 미루지 말라는 경고이기도 합니다.

## 1. 🔍 심층 분석
- **[TanStack Start Reaches 1.0](https://tanstack.com/blog/tanstack-start-1-0)** (출처: *React Status #494*)
  ![TanStack Start Reaches 1.0](https://res.cloudinary.com/cpress/image/upload/w_1280,e_sharpen:60,q_auto/ejihjkazanj4b02abevr.jpg)
   - 배경: Start는 타입 안전한 라우터(TanStack Router)를 만들다가 자연스럽게 풀스택으로 확장된 프레임워크입니다. 2026년 10월 13일 1.0 정식 출시로 RC 단계라는 단서가 사라졌고, 저자 Tanner Linsley는 API를 공식적으로 유지하겠다고 약속했습니다.
   - 핵심 기능: 라우트 단위로 서버 렌더링, 서버에서 데이터만 로드, 클라이언트 렌더링을 선택할 수 있습니다. 타입이 지정된 서버 함수와 클라이언트·서버를 오가는 미들웨어도 제공하며, 서버와 클라이언트 구현을 한곳에 나란히 쓰는 `createIsomorphicFn`이 대표적인 명시적 API입니다.
   - 코드 예제:
     ```tsx
     const getOrigin = createIsomorphicFn()
       .server(() => new URL(getRequest().url).origin)
       .client(() => window.location.origin)
     ```
   - 실무 적용: 기존 SPA 방식의 상태 관리와 클라이언트 내비게이션을 유지하면서 필요한 곳에만 서버를 쓰고 싶을 때 유용합니다. 공식 가이드는 Next.js와 RC에서의 마이그레이션 문서를 제공하며, 뉴스레터는 같은 앱을 Next.js 16.4와 비교한 서드파티 벤치마크(동적 요청 처리량 2.9~8.6배, 빌드 약 1.7배)도 소개했습니다.
   - 주의사항: RSC 지원은 Start의 핵심 모델과 분리된 옵트인 방식입니다. 저자는 tanstack.com에서는 RSC를 쓰다가 다시 제거했다고 밝혔고, npm에서 1.0이 `1.169`로 표기되는 점도 알아둘 만합니다.
- **[tsrs: Cloudflare and VoidZero's Rust Port of TypeScript](https://blog.cloudflare.com/typescript-rust-port/)** (출처: *JavaScript Weekly #807*)
   - 배경: Go로 포팅된 TypeScript 7이 이미 빠르지만, Rust는 Wasm 환경에서 가비지 컬렉터 없이 메모리를 효율적으로 다룰 수 있다는 장점이 있습니다. Cloudflare는 포크가 아니라 TypeScript 팀과 협업하는 충실한 포트임을 강조합니다.
   - 핵심 기능: 같은 타입 체크 워커 수 기준으로 TypeScript 7.0보다 최대 8배 빠르고 메모리는 약 70% 적게 사용한다고 합니다. Oxc 툴체인에서 인큐베이팅되며 WebAssembly로도 실행됩니다.
   - 코드 예제:
     ```bash
     npm install tsrs
     npx tsrs
     ```
   - 실무 적용: Oxlint의 타입 인지 린트 규칙 같은 통합이 예고되어 있고, 브라우저나 Workers 같은 샌드박스에서 개발 툴체인을 끝까지 돌리는 시나리오가 열립니다. 뉴스레터는 Owner.com이 사내 타입 체크를 80초에서 7초로 줄인 사례도 소개했습니다.
   - 주의사항: 아직 실험적 릴리스이며 진단 메시지 출력 순서 등 업스트림과의 차이가 남아 있습니다. TypeScript 7.1 베타도 7.0 대비 최대 2.5배 빨라졌다고 하니 비교 측정이 필요합니다.

## 3. 📝 추천 아티클 & 팁
- **[Native JSON Modules](https://allthingssmitty.com/2026/03/16/native-json-modules-are-finally-real/)** (출처: *Smashing Newsletter #581*)
  ![Native JSON Modules](https://mcusercontent.com/16b832d9ad4b28edf261f34df/images/20c7f37d-0d28-547a-9dc8-f931776d6f2b.png)
  + 배경: `import config from "./config.json"`은 네이티브처럼 보이지만 사실 번들러가 빌드 타임에 JSON을 모듈로 바꿔주던 것이었습니다. import attributes 덕분에 이제 런타임이 JSON 모듈을 직접 처리합니다.
  + 핵심 인사이트: `with { type: "json" }`는 "이 파일은 실행하지 말고 JSON으로 파싱하라"는 명시적 계약입니다. 파싱된 객체는 일반 ES 모듈처럼 한 번만 평가되고 캐시되므로 두 번 import해도 같은 객체입니다. 반면 번들러와 달리 기본적으로 번들에 인라인되지는 않습니다.
  + 코드 예시:
    ```js
    import config from "./config.json" with { type: "json" };
    const mod = await import("./config.json", { with: { type: "json" } });
    ```
  + 왜 유익한가: 번들러 없이 순수 ESM으로 JSON을 쓸 수 있다는 점뿐 아니라, 같은 패턴이 CSS 모듈 스크립트 등으로 확장된다는 큰 그림을 보여줍니다. 브라우저에서는 서버가 `Content-Type: application/json`을 보내야 하고 CORS 규칙이 그대로 적용된다는 실무 주의점도 짚어줍니다.
- **[Josh Comeau's The Future of CSS](https://www.joshwcomeau.com/css/interop-2027/)** (출처: *Frontend Focus #763*)
  + 배경: 브라우저 벤더들이 협업하는 Interop 프로젝트는 2027년 우선순위를 정하기 위해 제안 랭킹 투표를 열었고, 많은 개발자가 자신의 순위를 공유하고 있습니다. Josh의 글은 그중 상위 10개를 실제 데모와 브라우저 지원 현황과 함께 소개합니다.
  + 핵심 인사이트: CSS 함수, `corner-shape`, `border-shape`, 앵커드 컨테이너 쿼리, 스크롤 트리거 애니메이션, `reading-flow`, 갭 장식, 스크롤 상태 컨테이너 쿼리 등이 후보입니다. 글 작성 시점 기준 대부분 Chrome 155와 Edge 154에서만 지원되며 Firefox와 Safari는 미지원이지만, 점진적 향상으로 오늘부터 쓸 수 있는 것도 많습니다.
  + 코드 예시:
    ```css
    .grid {
      display: grid;
      reading-flow: grid-rows;
    }
    ```
  + 왜 유익한가: 반응형 레이아웃에서 시각 순서와 탭 순서가 어긋나는 접근성 문제를 `reading-flow` 한 줄로 푸는 방법처럼, 바로 쓸 수 있는 팁이 많습니다. 뉴스레터는 약 10개 제안에 투표하면 Firefox 팀에 유용한 입력이 된다고 소개했습니다.
- **[JPEG XL vs AVIF for Web Use-Cases](https://jakearchibald.com/2026/jpeg-xl-vs-avif/)** (출처: *Frontend Focus #763*)
  ![JPEG XL vs AVIF for Web Use-Cases](https://res.cloudinary.com/cpress/image/upload/w_1280,e_sharpen:60,q_auto/v1792585763/nrxh8gwtp2lom2spe99p.png)
  + 배경: JPEG XL이 모든 주요 브라우저에 들어왔고, Firefox 158이 기본 활성화에 합류한 최신 브라우저로 소개되었습니다.
  + 핵심 인사이트: Jake Archibald가 JPEG XL을 AVIF와 웹 사용 사례 기준으로 벤치마크해, 상세한 비교와 실무적인 결론을 정리했습니다.
  + 왜 유익한가: 이미지 포맷 전환을 검토할 때 인코딩 품질과 용도별 차이를 한 번에 확인할 수 있는 장문의 비교 글입니다.

## ✍️ 마치며
이번 주 소식을 관통하는 질문은 "도구가 빨라지면 무엇이 달라지는가"였던 것 같습니다. tsrs와 TypeScript 7.1이 보여주듯 타입 체크가 몇 배 빨라지면 타입을 엄격하게 쓰는 비용이 줄어듭니다. TanStack Start 1.0의 타입 안전성과 명시적 API가 에이전트 시대에 더 큰 힘을 발휘한다는 저자의 관찰도, 결국 같은 맥락에서 읽힙니다.

반대로 Next.js와 PHP의 RCE 패치는 속도와 편의성 이면의 부담을 상기시킵니다. 프레임워크를 고를 때 성능 수치만큼이나 업데이트 대응 체계와 공격 표면을 함께 살펴야 한다는 생각이 듭니다. 웹 플랫폼이 JSON 모듈과 CSS 기능으로 번들러의 역할을 흡수해 가는 흐름도 같은 방향으로 보입니다. 빌드 단계에서 하던 일이 런타임과 언어 표준으로 이동할수록 우리가 알아야 할 것은 도구 사용법보다 플랫폼 자체의 동작이 됩니다.
