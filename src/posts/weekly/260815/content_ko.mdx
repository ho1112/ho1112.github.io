## 1. 🔍 심층 분석
- **[How Baseline Can Help You Ship Less JavaScript](https://www.smashingmagazine.com/2026/08/how-baseline-can-help-ship-less-javascript/)** (출처: *JavaScript Weekly #798*)
  - 배경: 폴리필과 유틸 라이브러리가 관성처럼 쌓이지만, 브라우저 지원 기준선(Baseline)이 올라오면서 상당수는 이제 네이티브로 대체 가능합니다. 이 글은 "무엇을 지울 수 있는가"를 감으로 판단하지 말고 재사용 가능한 감사 절차로 만들자고 제안합니다.
  - 핵심 기능: 의존성을 Intl, HTTP, UI 프리미티브, lodash 같은 클러스터로 묶고, 삭제 전에 던져야 할 질문 목록을 제공합니다. 흥미롭게도 교체가 오히려 번들을 키우는 사례(Day.js → Temporal)까지 짚어, 무조건적인 "라이브러리 제거"를 경계합니다.
  - 코드 예제:
```js
    // 포맷팅 유틸 라이브러리 대신 네이티브 Intl 사용
    const price = new Intl.NumberFormat("ko-KR", {
      style: "currency", currency: "KRW",
    }).format(19900); // "₩19,900"
    const rtf = new Intl.RelativeTimeFormat("ko");
    rtf.format(-1, "day"); // "1일 전"
```
  - 실무 적용: 신규 기능 추가 전 "이 기능, Baseline에 들어왔나?"를 체크리스트로 두면 의존성 증가를 사전에 막을 수 있습니다.
  - 주의사항: 네이티브 API가 항상 더 가벼운 것은 아닙니다. 폴리필(Temporal 등)이 아직 무거운 영역에서는 교체가 역효과일 수 있으므로 실제 번들 크기를 측정한 뒤 결정해야 합니다.
- **[Rebuilding FIFA Standings Layout With CSS Subgrid](https://ishadeed.com/article/fifa-layout/)** (출처: *Smashing Newsletter #571*)
  ![Rebuilding FIFA Standings Layout With CSS Subgrid](https://mcusercontent.com/16b832d9ad4b28edf261f34df/images/326ae1b0-350e-96fb-587d-b657a7a9f5cd.png)
  - 배경: Ahmad Shadeed가 월드컵 순위표 페이지에 호기심을 느껴 원본 구현을 뜯어본 뒤, 같은 레이아웃을 CSS grid와 subgrid로 다시 만들어 본 과정을 정리했습니다.
  - 핵심 기능: 바깥 그리드에서 컬럼 트랙을 한 번만 정의하고, 각 행(카드/팀)이 subgrid로 그 트랙을 그대로 물려받게 하는 것이 핵심입니다. 이렇게 하면 행마다 컬럼 폭을 따로 맞출 필요 없이 정렬이 자동으로 일치합니다.
  - 코드 예제:
```css
    .table { display: grid; grid-template-columns: 2rem 1fr repeat(4, 3rem); }
    .row {
      display: grid;
      grid-column: 1 / -1;
      grid-template-columns: subgrid; /* 부모 트랙을 그대로 상속 */
    }
```
  - 실무 적용: 순위표, 가격표, 데이터 카드처럼 "행마다 셀 경계가 딱 맞아야 하는" 레이아웃에서 별도 테이블 마크업 없이 시맨틱을 유지하며 정렬할 수 있습니다.
  - 주의사항: subgrid는 비교적 최신 기능이므로, 구형 브라우저 대비 폴백(단순 flex 정렬 등)을 함께 설계하는 것이 안전합니다.

## 2. 🛠️ 툴 & 라이브러리
- **[GTKX 1.0: The React Framework for Linux](https://gtkx.dev/blog/gtkx-1-0)** (출처: *React Status #487*)
  + 개요: React(JSX)로 네이티브 리눅스 데스크톱 앱을 만드는 프레임워크입니다. webview 없이 실제 GTK4·Adwaita 위젯을 렌더링하며, 일반 Node 프로세스에서 npm 패키지와 Fast Refresh까지 사용할 수 있습니다.
  + 사용법: 1.0 직후 나온 GTKX 1.1은 배포까지 한 번에 처리하는 명령을 추가했습니다.
```bash
    # Flatpak / .deb / .rpm / AppImage 배포물을 한 번에 생성 (GTKX 1.1)
    gtkx deploy
```
  + 실전 팁: Electron식 webview 방식이 부담스러웠던 리눅스 타깃 앱이라면, 웹 스택(React) 경험을 그대로 살리면서 네이티브 위젯의 성능·룩앤필을 챙길 수 있는 선택지가 됩니다.
- **[TermDOM: Build Terminal UIs with HTML, CSS and the DOM](https://termdom.org/)** (출처: *Frontend Focus #754*)
  + 개요: Crank.js 제작자가 만든 프로젝트로, 웹 개발 스킬을 터미널로 가져옵니다. Node·Bun·Deno 기반의 TUI를 바닐라 JS 또는 임의의 프런트엔드 프레임워크로 작성할 수 있습니다.
  + 사용법(개념 예시): 익숙한 DOM API로 터미널 화면 요소를 구성하는 형태입니다.
```js
    // DOM 스타일 API로 터미널 UI 노드를 구성하는 개념 예시
    const box = document.createElement("div");
    box.style.border = "1px solid";
    box.textContent = "Hello Terminal";
    document.body.appendChild(box);
```
  + 실전 팁: Flexbox와 폼은 지원하지만 CSS Grid는 아직 미지원입니다. 레이아웃은 Flexbox 기준으로 설계하세요.

## ✍️ 마치며
이번 주 소식을 관통하는 인상은, 프런트엔드가 다시 "표준 플랫폼"으로 무게중심을 옮기고 있다는 점입니다. Baseline을 근거로 의존성을 걷어내고, subgrid와 편집용 타이포그래피처럼 예전엔 라이브러리나 이미지로 우회하던 표현을 이제 CSS 한두 줄로 해결합니다. 라이브러리를 더하는 대신 플랫폼이 제공하는 것을 먼저 확인하는 습관이, 장기적으로는 번들 크기뿐 아니라 유지보수 비용까지 줄여 준다는 생각이 듭니다. 한편 Kitesurf처럼 "사람이 아닌 에이전트를 위한 브라우저"가 등장하는 흐름은, 우리가 만드는 웹의 소비 주체가 넓어지고 있음을 상기시킵니다. 도구가 빨라지고(TypeScript 7.0, pnpm 12) 표준이 두터워지는 지금이야말로, 습관처럼 쌓아 온 스택을 한 번쯤 점검해 볼 좋은 시점이라고 느낍니다.
