## 🔥 今週の主要テーマ

今週は「**送らないことこそパフォーマンス**」というテーマが複数のニュースレターを貫いていました。JavaScript WeeklyはBaselineを基準に依存関係を監査(audit)し、バンドルを削減する方法を、Frontend FocusはJavaScriptなしでリアルタイムSPAを実装するアプローチを取り上げました。同時に、CSSの表現力が大きく伸びたことも目を引きます。subgridで複雑な表レイアウトを再現したり、background-clipや編集用タイポグラフィ機能でテキストデザインを引き上げたりする記事が続きました。ツール面では、ReactでネイティブなLinuxアプリを作るGTKX 1.0、ターミナルUIをDOMで作るTermDOMが登場し、リリース欄にはNode.js 26.7、Next.js 16.3.1、TypeScript 7.0(ネイティブポート)まで大きなニュースが集まりました。

## 1. 🔍 深掘り
- **[How Baseline Can Help You Ship Less JavaScript](https://www.smashingmagazine.com/2026/08/how-baseline-can-help-ship-less-javascript/)** (出典: *JavaScript Weekly #798*)
  - 背景: ポリフィルやユーティリティライブラリは惰性のように積み重なっていきますが、ブラウザのサポート基準線(Baseline)が上がるにつれて、その多くは今やネイティブに置き換え可能になっています。この記事は、「何を削除できるか」を勘で判断するのではなく、再利用可能な監査プロセスとして仕組み化しようと提案しています。
  - 主な機能: 依存関係をIntl、HTTP、UIプリミティブ、lodashのようなクラスターにまとめ、削除前に投げかけるべき質問リストを提供します。興味深いことに、置き換えがかえってバンドルを大きくしてしまう事例(Day.js → Temporal)まで取り上げ、無条件の「ライブラリ削除」に警鐘を鳴らしています。
  - コード例:
```js
    // フォーマット用ユーティリティライブラリの代わりにネイティブのIntlを使用
    const price = new Intl.NumberFormat("ko-KR", {
      style: "currency", currency: "KRW",
    }).format(19900); // "₩19,900"
    const rtf = new Intl.RelativeTimeFormat("ko");
    rtf.format(-1, "day"); // "1日前"
```
  - 実務への適用: 新機能を追加する前に「この機能、Baselineに入っているか?」をチェックリストにしておけば、依存関係の増加を事前に防ぐことができます。
  - 注意事項: ネイティブAPIが常に軽いとは限りません。ポリフィル(Temporalなど)がまだ重い領域では、置き換えが逆効果になる可能性があるため、実際のバンドルサイズを測定してから判断する必要があります。
- **[Rebuilding FIFA Standings Layout With CSS Subgrid](https://ishadeed.com/article/fifa-layout/)** (出典: *Smashing Newsletter #571*)
  ![Rebuilding FIFA Standings Layout With CSS Subgrid](https://mcusercontent.com/16b832d9ad4b28edf261f34df/images/326ae1b0-350e-96fb-587d-b657a7a9f5cd.png)
  - 背景: Ahmad Shadeed氏がワールドカップの順位表ページに興味を持ち、元の実装を分解して調べた上で、同じレイアウトをCSS gridとsubgridで作り直した過程をまとめています。
  - 主な機能: 外側のグリッドでカラムトラックを一度だけ定義し、各行(カード/チーム)がsubgridでそのトラックをそのまま継承する点がポイントです。こうすることで、行ごとにカラム幅を個別に合わせる必要がなく、配置が自動的に揃います。
  - コード例:
```css
    .table { display: grid; grid-template-columns: 2rem 1fr repeat(4, 3rem); }
    .row {
      display: grid;
      grid-column: 1 / -1;
      grid-template-columns: subgrid; /* 親のトラックをそのまま継承 */
    }
```
  - 実務への適用: 順位表、価格表、データカードのように「行ごとにセルの境界がぴったり揃う必要がある」レイアウトで、別途テーブルマークアップを使わずにセマンティックを保ちながら整列できます。
  - 注意事項: subgridは比較的新しい機能なので、旧型ブラウザ向けのフォールバック(単純なflex整列など)を併せて設計しておくのが安全です。

## 2. 🛠️ ツール & ライブラリ
- **[GTKX 1.0: The React Framework for Linux](https://gtkx.dev/blog/gtkx-1-0)** (出典: *React Status #487*)
  + 概要: React(JSX)でネイティブなLinuxデスクトップアプリを作るフレームワークです。webviewを使わずに実際のGTK4・Adwaitaウィジェットをレンダリングし、通常のNodeプロセス上でnpmパッケージやFast Refreshまで利用できます。
  + 使い方: 1.0直後に登場したGTKX 1.1では、デプロイまで一括で処理するコマンドが追加されました。
```bash
    # Flatpak / .deb / .rpm / AppImageの配布物を一括生成 (GTKX 1.1)
    gtkx deploy
```
  + 実践チップ: Electron式のwebview方式が負担に感じられたLinux向けアプリなら、Webスタック(React)の経験をそのまま活かしつつ、ネイティブウィジェットの性能・ルックアンドフィールを両立できる選択肢になります。
- **[TermDOM: Build Terminal UIs with HTML, CSS and the DOM](https://termdom.org/)** (出典: *Frontend Focus #754*)
  + 概要: Crank.jsの作者が手がけたプロジェクトで、Web開発のスキルをターミナルに持ち込みます。Node・Bun・Deno上のTUIを、バニラJSまたは任意のフロントエンドフレームワークで記述できます。
  + 使い方(概念例): おなじみのDOM APIでターミナル画面の要素を構成する形です。
```js
    // DOMスタイルのAPIでターミナルUIノードを構成する概念例
    const box = document.createElement("div");
    box.style.border = "1px solid";
    box.textContent = "Hello Terminal";
    document.body.appendChild(box);
```
  + 実践チップ: FlexboxとフォームはサポートしていますがCSS Gridはまだ未対応です。レイアウトはFlexboxを基準に設計してください。

## 3. 📝 おすすめ記事 & チップ
- **[Five CSS Properties You Should Know for Better Text Designs](https://master.dev/blog/typographic-css-tricks/)** (出典: *Frontend Focus #754*)

```css
    }
```

## ✍️ おわりに
今週のニュースを貫く印象は、フロントエンドが再び「標準プラットフォーム」へと重心を移しつつあるという点です。Baselineを根拠に依存関係を削ぎ落とし、subgridや編集用タイポグラフィのように、かつてはライブラリや画像で迂回していた表現を、今やCSS一、二行で解決しています。ライブラリを追加する前にプラットフォームが提供するものをまず確認する習慣が、長期的にはバンドルサイズだけでなく保守コストまで削減してくれるように思います。一方、Kitesurfのように「人間ではなくエージェントのためのブラウザ」が登場する流れは、私たちが作るWebの消費主体が広がりつつあることを思い出させてくれます。ツールが高速化し(TypeScript 7.0、pnpm 12)、標準が厚みを増しつつある今こそ、習慣のように積み上げてきたスタックを一度見直してみるいい時期だと感じます。
