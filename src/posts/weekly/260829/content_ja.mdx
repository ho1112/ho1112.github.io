## 🔥 今週の主要テーマ

今週は「フレームワーク大移動」と「AI時代のフロントエンド」という二つの軸がはっきりと見えました。Lovableが4200万MAU規模のサービスをNext.jsからTanStack Startへルート単位で移行した大規模マイグレーションの記録が話題を呼び、Frontend Focusのカバーストーリーは、AI回答時代におけるフロントエンド知識の価値がどう再編されるかを正面から取り上げました。同時にBun 1.4、Solid 2.0 RC、SvelteKit 3 RCといった大型リリースが相次ぎ、CSS Custom Highlight APIやHTMLの基本機能がJavaScriptの領域を吸収していく流れも続いています。Smashingは今回、UXリサーチ特集で毛色の違う内容を届けています。

## 1. 🔍 深掘り
- **[How Lovable Migrated from Next.js to TanStack Start](https://lovable.dev/blog/how-we-migrated-lovable-dev-away-from-nextjs)** (出典: *React Status #488*)
  - 背景: lovable.devは月間4200万訪問者、約400ルート、85万〜91万行規模のアプリを、Vercel上のNext.jsから自社インフラ(Cloudflare)上のTanStack Startへ移行しました。動機は明確です。ローカル開発サーバーの起動時間が70秒・8GB RAMから10秒・1.5GBに短縮され、クライアント中心のアプリではサーバーファーストのApp Routerがもたらす利点があまり大きくなかったのです。
  - 主な特徴: 両フレームワークをプロキシワーカーの背後で同時に稼働させ、ルートレジストリとフィーチャーフラグのメタデータを単一の信頼できる情報源として抽出し、プロキシと両フレームワークで共有しました。ラップされたルーターコンポーネントがソフト/ハードナビゲーションを判定し、ルートグループごとに社内 → 1% → 100%の多段階A/Bロールアウトを行いました。あるユーザーが最初に着地したフレームワークにそのまま留まり続けるよう固定した点もポイントです。
  - コード例(概念的な流れ):
```js
    // ルートレジストリとフィーチャーフラグを単一のソースとして
    // プロキシがリクエストをどちらかのフレームワークに振り分ける
    const target = pickFramework(routeRegistry, request.url, user.flags);
    return target === "tanstack"
      ? fetch(TANSTACK_ORIGIN + path, request)
      : fetch(NEXTJS_ORIGIN + path, request);
```
  - 実務への応用: 大規模なクライアント中心アプリを無停止で段階的に移行する際の、ストラングラーパターンの教科書的な事例です。最終的にフレームワーク依存のコードは全体の約3%まで減少しました。
  - 注意事項: 静的JSON importが一つ、CloudflareのIsolateにおける128MBのメモリ上限を超え、11分間エラー率50%を引き起こしたOOM事故がありました。また、外部ロールアウトは一度に一つずつ1%→100%へ上げないと混乱を招くとのことです。
- **[ESM and CommonJS: What import and require Actually Do](https://blog.gaborkoos.com/posts/2026-08-14-Your-Modules-Are-Lying-to-You/)** (出典: *JavaScript Weekly #799*)
  - 背景: JavaScriptには長らく標準のモジュールシステムがなく、Nodeがその空白をCommonJSで埋めました。2015年にESMが標準として登場したことで両体系が共存するようになり、その相互運用の境界に微妙な落とし穴が生まれています。
  - 主な特徴: `import`と`require`は「コードを読み込む」という一つの概念の裏に、解決・インスタンス化・評価・公開という4段階を隠しています。ESMのnamed importはエクスポート元のモジュールが所有するバインディングへの生きた参照である一方、CommonJSは`module.exports`オブジェクトの値を返すため、分割代入で取り出した値はその時点のコピーになります。また、静的importはソース上の位置に関係なく、エントリーモジュールの評価前にグラフが先に構築されます。
  - コード例:
```js
    // counter.mjs
    export let count = 0;
    export const inc = () => { count++; };

    // app.mjs — importは生きたバインディング(live binding)
    import { count, inc } from "./counter.mjs";
    inc();
    console.log(count); // 1  (値の変化がそのまま見える)
```
  - 実務への応用: 循環依存、デュアルパッケージ、「importではできるがrequireではできない」パッケージ問題の根本を理解するのに直接役立ちます。
  - 注意事項: 循環ESM importはTDZにより`ReferenceError`が発生することがあり、ESMは相対パスに拡張子を要求し、`__dirname`の代わりに`import.meta.url`を使う必要があります。

## 2. 🛠️ ツール & ライブラリ
- **[MicroLighter: A Syntax Highlighter That Doesn't Touch the DOM](https://daverupert.com/2026/08/microlighter/)** (出典: *Frontend Focus #755*)
  + 概要: Dave Rupertが作った約2KBのクライアントサイドハイライターで、トークンごとに`<span>`を挿入する代わりにCSS Custom Highlight APIの`::highlight()`を使用します。VS Codeが使うTextMate構文を必要なときだけ遅延読み込みし、この手法は今年Baselineに入りました。
  + 使い方:
```js
    import { highlightAll } from "microlighter";
    import "microlighter/themes/github.css";

    await highlightAll(); // pre>codeブロックをスキャンしてハイライト
```
  + 実践Tips: `::highlight()`はイタリック・ボールド・フォント変更に対応していないという制限があるため、行番号やコピーボタンが必要な場合はカスタムエレメント版を使うとよいでしょう。ページ読み込み後に挿入されたコードは、再ハイライトイベントで更新できます。
- **[TermDOM: Build Terminal UIs with HTML, CSS and DOM](https://termdom.org/)** (出典: *JavaScript Weekly #799*)
  + 概要: 実際のDOM・CSSOMとレイアウトエンジンを文字セルのグリッドにレンダリングし、独自のウィジェットAPIを覚えなくてもバニラJSやReact/Vue/Angularの標準レンダラーでTUIを作れるようにします。今回のv0.1.5でCSS gridに対応しました。
  + 使い方:
```js
    import { TermDOM } from "@b9g/termdom";

    const term = new TermDOM();
    term.attach(); // 実際のDOMドキュメントがターミナルに描画される
    term.document.body.innerHTML = "<div>Hello, terminal</div>";
```
  + 実践Tips: `1px`と`1ch`はどちらも1セルにマッピングされ、`@media`クエリは実際のターミナルサイズに反応してリフローします。Node・Bun・Denoで動作し、単一バイナリにコンパイルすることもできます。

## ✍️ おわりに

今週のニュースを貫く流れは「削ぎ落とし」でした。Lovableはフレームワーク依存コードを3%まで削ぎ落とし、MicroLighterは`<span>`の挿入を削ぎ落とし、Alex Russellは読み込みタイミングを調整するよりコード自体を送らないほうがいいと語ります。HTMLとCSSがJavaScriptの領域を吸収していく流れも、結局は同じ方向を向いています。プラットフォームが成熟するほど、私たちが直接背負うべき複雑さは減っていきます。ただ、Lovableの11分間の障害が思い起こさせるように、抽象化を取り除いた場所には、メモリの上限のような根本的な制約がより鮮明に現れます。何をフレームワークに任せ、何を自分で理解すべきかを見極める感覚が、AIが表面的な知識を代替する時代にこそ、むしろ重要になっていると感じます。
