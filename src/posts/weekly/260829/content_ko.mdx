## 🔥 이번 주 핵심 테마

이번 주는 "프레임워크 대이동"과 "AI 시대의 프론트엔드"라는 두 축이 뚜렷했습니다. Lovable이 42M MAU 규모 서비스를 Next.js에서 TanStack Start로 라우트 단위로 옮긴 대규모 마이그레이션 기록이 화제였고, Frontend Focus의 커버 스토리는 AI 답변 시대에 프론트엔드 지식의 가치가 어떻게 재편되는지를 정면으로 다뤘습니다. 동시에 Bun 1.4, Solid 2.0 RC, SvelteKit 3 RC 등 굵직한 릴리스가 쏟아졌고, CSS Custom Highlight API와 HTML 기본 기능이 자바스크립트의 영역을 흡수하는 흐름도 계속됐습니다. ## 1. 🔍 심층 분석
- **[How Lovable Migrated from Next.js to TanStack Start](https://lovable.dev/blog/how-we-migrated-lovable-dev-away-from-nextjs)** (출처: *React Status #488*)
  - 배경: lovable.dev는 월 42M 방문자, 약 400개 라우트, 85만~91만 줄 규모의 앱을 Vercel 위 Next.js에서 자체 인프라(Cloudflare) 위 TanStack Start로 옮겼습니다. 동기는 명확합니다. 로컬 개발 서버 기동이 70초·8GB RAM에서 10초·1.5GB로 줄었고, 클라이언트 중심 앱에서는 서버 우선 App Router가 주는 이점이 크지 않았습니다.
  - 핵심 기능: 두 프레임워크를 프록시 워커 뒤에서 동시에 구동하고, 라우트 레지스트리와 피처 플래그 메타데이터를 단일 진실 공급원으로 추출해 프록시와 양쪽 프레임워크가 공유했습니다. 래핑된 라우터 컴포넌트가 소프트/하드 내비게이션을 판단하고, 라우트 그룹별로 내부 → 1% → 100%의 다단계 A/B 롤아웃을 진행했습니다. 한 사용자가 처음 착지한 프레임워크에 계속 머무르도록 고정한 것도 포인트입니다.
  - 코드 예제 (개념적 흐름):
```js
    // 라우트 레지스트리 + 피처 플래그를 단일 소스로 삼아
    // 프록시가 요청을 두 프레임워크 중 하나로 분배한다
    const target = pickFramework(routeRegistry, request.url, user.flags);
    return target === "tanstack"
      ? fetch(TANSTACK_ORIGIN + path, request)
      : fetch(NEXTJS_ORIGIN + path, request);
```
  - 실무 적용: 대형 클라이언트 중심 앱을 무중단으로 점진 이전할 때의 스트랭글러 패턴 교과서입니다. 최종적으로 프레임워크 종속 코드는 전체의 약 3%까지 줄었습니다.
  - 주의사항: 정적 JSON import 하나가 Cloudflare isolate의 128MB 메모리 한계를 넘겨 11분간 오류율 50%를 유발한 OOM 사고가 있었습니다. 또한 외부 롤아웃은 한 번에 하나만 1%→100%로 올려야 혼선을 막을 수 있었다고 합니다.
- **[ESM and CommonJS: What import and require Actually Do](https://blog.gaborkoos.com/posts/2026-08-14-Your-Modules-Are-Lying-to-You/)** (출처: *JavaScript Weekly #799*)
  - 배경: 자바스크립트는 오랫동안 표준 모듈 시스템이 없었고, Node가 CommonJS로 그 공백을 메웠습니다. 2015년 ESM이 표준으로 등장하면서 두 체계가 공존하게 됐고, 그 상호운용 경계에서 미묘한 함정이 생깁니다.
  - 핵심 기능: `import`와 `require`는 "코드를 불러온다"는 하나의 개념 뒤에 해석·인스턴스화·평가·노출이라는 네 단계를 숨깁니다. ESM의 named import는 내보내는 모듈이 소유한 바인딩에 대한 살아있는 참조인 반면, CommonJS는 `module.exports` 객체의 값을 돌려주므로 구조 분해로 꺼낸 값은 그 시점의 복사본이 됩니다. 또한 정적 import는 소스 상 위치와 무관하게 진입 모듈 평가 전에 그래프가 먼저 구성됩니다.
  - 코드 예제:
```js
    // counter.mjs
    export let count = 0;
    export const inc = () => { count++; };

    // app.mjs — import는 살아있는 바인딩(live binding)
    import { count, inc } from "./counter.mjs";
    inc();
    console.log(count); // 1  (값 변화가 그대로 보인다)
```
  - 실무 적용: 순환 의존성, 듀얼 패키지, "import로는 되는데 require로는 안 되는" 패키지 문제의 근본을 이해하는 데 직접적으로 도움이 됩니다.
  - 주의사항: 순환 ESM import는 TDZ로 인해 `ReferenceError`가 날 수 있고, ESM은 상대 경로에 확장자를 요구하며, `__dirname` 대신 `import.meta.url`을 써야 합니다.

## 2. 🛠️ 툴 & 라이브러리
- **[MicroLighter: A Syntax Highlighter That Doesn't Touch the DOM](https://daverupert.com/2026/08/microlighter/)** (출처: *Frontend Focus #755*)
  + 개요: Dave Rupert가 만든 약 2KB 클라이언트 사이드 하이라이터로, 토큰마다 `<span>`을 주입하는 대신 CSS Custom Highlight API의 `::highlight()`를 사용합니다. VS Code가 쓰는 TextMate 문법을 필요할 때만 지연 로드하며, 이 기법은 올해 Baseline에 올랐습니다.
  + 사용법:
```js
    import { highlightAll } from "microlighter";
    import "microlighter/themes/github.css";

    await highlightAll(); // pre>code 블록을 스캔해 하이라이트
```
  + 실전 팁: `::highlight()`는 이탤릭·볼드·폰트 교체를 지원하지 않는 한계가 있으니, 줄 번호나 복사 버튼이 필요하면 커스텀 엘리먼트 버전을 쓰면 됩니다. 페이지 로드 후 삽입된 코드는 재하이라이트 이벤트로 갱신할 수 있습니다.
- **[TermDOM: Build Terminal UIs with HTML, CSS and DOM](https://termdom.org/)** (출처: *JavaScript Weekly #799*)
  + 개요: 실제 DOM·CSSOM과 레이아웃 엔진을 문자 셀 격자에 렌더링해, 별도 위젯 API를 배우지 않고 바닐라 JS 혹은 React/Vue/Angular의 표준 렌더러로 TUI를 만들 수 있게 해줍니다. 이번 v0.1.5에서 CSS grid를 지원합니다.
  + 사용법:
```js
    import { TermDOM } from "@b9g/termdom";

    const term = new TermDOM();
    term.attach(); // 실제 DOM 문서가 터미널에 그려진다
    term.document.body.innerHTML = "<div>Hello, terminal</div>";
```
  + 실전 팁: `1px`와 `1ch`가 모두 한 셀로 매핑되며, `@media` 쿼리가 실제 터미널 크기에 반응해 리플로우됩니다. Node·Bun·Deno에서 동작하고 단일 바이너리로 컴파일할 수도 있습니다.

## ✍️ 마치며

이번 주 소식을 관통하는 흐름은 "덜어내기"였습니다. Lovable은 프레임워크 종속 코드를 3%까지 덜어냈고, MicroLighter는 `<span>` 주입을 덜어냈으며, Alex Russell은 로딩 시점을 조율하기보다 코드 자체를 덜 보내라고 말합니다. HTML과 CSS가 자바스크립트의 영역을 흡수하는 흐름도 결국 같은 방향입니다. 플랫폼이 성숙해질수록 우리가 직접 떠안아야 할 복잡성은 줄어듭니다. 다만 Lovable의 11분 장애가 상기시키듯, 추상화를 걷어낸 자리에는 메모리 한계 같은 근본적인 제약이 더 선명하게 드러납니다. 무엇을 프레임워크에 맡기고 무엇을 직접 이해할지 구분하는 감각이, AI가 표면적인 지식을 대체하는 시대에 오히려 더 중요해지고 있다고 느낍니다.
