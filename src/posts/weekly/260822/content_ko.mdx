## 🔥 이번 주 핵심 테마

이번 주 프론트엔드 생태계의 화두는 단연 **AI 에이전트 시대의 프레임워크 선택**입니다. Cursor가 Solid를 버리고 React와 StyleX로 완전히 이주한 사실이 공개된 바로 그 주에, Solid는 async를 반응형 그래프의 일급 시민으로 끌어올린 Solid 2.0 RC를 공개하며 정면 승부를 걸었습니다. 한편 GitHub의 8시간 장애는 Cursor, Cloudflare, Pierre가 각자의 Git 호스팅을 들고나오는 이른바 "Git War of 2026"의 방아쇠가 되었습니다. 여기에 pnpm 12, Vitest 5, SvelteKit 3, Preact 11, 그리고 React Native 0.87까지 메이저 버전 RC가 쏟아진 한 주였습니다.

## 1. 🔍 심층 분석
- **[Solid 2.0 RC: The Big \<Reveal\>](https://www.solidjs.com/blog/solid-2-0-rc-the-big-reveal)** (출처: *Bytes #513*)
  - 배경: UI 프레임워크의 진짜 난제는 렌더링이 아니라 async였습니다. Solid 1.x는 비동기 값을 `createResource`라는 특수 프리미티브로 따로 처리해야 했는데, 2.0은 이 async를 반응형 그래프의 **일급 시민**으로 통합하며 프레임워크 역사상 가장 큰 개편을 단행했습니다.
  - 핵심 기능: `createMemo`에 Promise나 async iterator를 그대로 넘기면 그래프가 suspend/resume을 자동 처리합니다. `<Suspense>`는 첫 렌더만 담당하는 `<Loading>`으로 대체되었고, 갱신은 `isPending()`으로 백그라운드에서 추적되어 재검증 때마다 UI가 스피너로 되돌아가지 않습니다. `action()`과 `createOptimisticStore` 같은 낙관적 프리미티브가 코어에 들어왔고, Oxc 기반 Rust 컴파일러로 빌드가 기존 대비 20~350배 빨라졌습니다.
  - 코드 예제:
```js
    // Solid 1.x — resource로 특수 처리
    const [data] = createResource(() => fetchUser(userId()));

    // Solid 2.0 — <Loading> 경계 안에서 Promise를 그대로
    const data = createMemo(() => fetchUser(userId()));
```
  - 실무 적용: 데이터가 많은 화면에서 재검증이 일어나도 이전 콘텐츠가 화면에 남아 있어, 값을 읽는 지점에서만 블로킹됩니다. 개별 데이터가 준비되는 즉시 UI가 갱신되는 경험을 만들 때 특히 강력합니다.
  - 주의사항: 아직 RC 단계라 API가 stable 전까지 바뀔 수 있습니다. 또한 `await` 경계 뒤에서 시그널을 읽으면 추적이 끊기므로, **먼저 track하고 그다음 await**하는 순서를 지켜야 합니다.
- **[The Git War of 2026](https://github.blog/news-insights/company-news/the-august-17-outage-and-the-work-ahead/)** (출처: *Bytes #514*)
  - 배경: GitHub은 이제 월 30억 건의 커밋을 처리하고 1억 3천만 개의 PR을 머지하는데, 이 부하 때문에 시스템이 한계에 부딪혔습니다. 최근 8시간 장애 동안 세 팀이 동시에 경쟁 제품을 출시하며 "Git War"가 시작되었습니다.
  - 핵심 기능 (경쟁자 아키텍처):
    - **Cursor Origin** — GitHub 아키텍트를 영입해 만든 새 Git 호스팅 아키텍처로, 더 빠르고 안정적인 것을 목표로 합니다. 코드 리뷰 UI는 있지만 CI/CD는 아직 직접 붙여야 합니다.
    - **Pierre Computer Co.** — 역시 전직 GitHub 출신 팀이 만든 API-only 방식의 Git 스토리지로, 이미 Lovable과 Bolt가 사용 중입니다.
    - **Cloudflare Artifacts** — "Git을 말하는 버전 스토리지"로, 사실상 "Cloudflare 위에 GitHub를 셀프호스트"하는 개념입니다. 버전 스토리지, 파이프라인, 이벤트, CI 같은 빌딩 블록을 제공합니다.
  - 실무 적용: 에이전트가 코드를 대량 생성하는 시대에, 폭증하는 커밋·PR을 감당할 Git 인프라를 고민하는 팀에게 새로운 선택지들이 열렸습니다.
  - 주의사항: 세 제품 모두 현재 형태로는 GitHub의 완전한 대체재는 아닙니다. 아직은 부하를 나눠 지는 보완재에 가깝습니다.

## 2. 🛠️ 툴 & 라이브러리
- **[MicroLighter](https://daverupert.com/2026/08/microlighter/)** (출처: *Bytes #513*)
  + 개요: Dave Rupert가 만든 의존성 없는 클라이언트 사이드 구문 하이라이터로, CSS Custom Highlight API를 사용합니다. 토큰마다 `<span>`을 주입하지 않고 텍스트 범위를 `CSS.highlights`에 등록하는 방식이라 DOM이 깨끗하게 유지됩니다.
  + 사용법:
```js
    import { highlightAll } from "microlighter";
    import "microlighter/themes/github.css";
    await highlightAll();
    // <pre><code class="language-javascript">const answer = 42;</code></pre>
```
  + 실전 팁: 코드가 없는 페이지에서는 스크립트를 지연 로딩해 불필요한 비용을 줄일 수 있습니다. 다만 `::highlight()` 의사요소는 italic, bold, 폰트 교체를 지원하지 않는 한계가 있으니, 그런 기능이 필요하면 web component 번들을 함께 쓰면 됩니다.

## ✍️ 마치며

이번 주 소식을 정리하다 보면, 프레임워크의 기술적 우수성과 '에이전트가 얼마나 잘 다루느냐'가 점점 다른 축으로 갈라지고 있다는 인상을 받습니다. Cursor가 Solid를 떠난 이유가 성능이나 표현력이 아니라 "에이전트가 React를 더 예측 가능하게 짠다"였다는 점은 곱씹어 볼 만합니다. 그리고 바로 그 주에 Solid 2.0이 async 복잡성을 프레임워크가 흡수해 "에이전트가 망칠 여지를 줄이겠다"는 방향으로 응수한 것은, 앞으로의 경쟁 구도를 상징적으로 보여줍니다.

GitHub 장애가 촉발한 Git 인프라 경쟁도 결국 같은 흐름의 연장선으로 읽힙니다. 사람의 속도가 아니라 에이전트의 속도로 코드가 쏟아지면서, 우리가 당연하게 여겨온 인프라의 전제들이 다시 시험대에 오르고 있습니다. 쏟아지는 메이저 RC들 속에서 각 도구가 'AI 시대의 워크플로우'에 어떻게 스스로를 맞춰가는지 지켜보는 일은, 당분간 가장 흥미로운 관전 포인트가 될 것 같습니다.
