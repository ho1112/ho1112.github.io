## 🔥 今週の主要テーマ

今週のフロントエンドエコシステムの話題は、なんといっても**AIエージェント時代のフレームワーク選択**です。CursorがSolidを捨ててReactとStyleXへ完全移行した事実が公開されたまさにその週に、Solidはasyncをリアクティブグラフの一級市民へと引き上げたSolid 2.0 RCを公開し、真っ向勝負を挑みました。一方、GitHubの8時間障害は、Cursor、Cloudflare、Pierreがそれぞれ独自のGitホスティングを打ち出す、いわゆる「Git War of 2026」の引き金となりました。さらにpnpm 12、Vitest 5、SvelteKit 3、Preact 11、そしてReact Native 0.87まで、メジャーバージョンのRCが相次いだ一週間でした。

## 1. 🔍 深掘り
- **[Solid 2.0 RC: The Big \<Reveal\>](https://www.solidjs.com/blog/solid-2-0-rc-the-big-reveal)** (出典: *Bytes #513*)
  - 背景: UIフレームワークの本当の難題は、レンダリングではなくasyncでした。Solid 1.xでは非同期の値を`createResource`という特殊なプリミティブで別途処理する必要がありましたが、2.0ではこのasyncをリアクティブグラフの**一級市民**として統合し、フレームワーク史上最大の刷新を行いました。
  - 主な機能: `createMemo`にPromiseやasync iteratorをそのまま渡すと、グラフがsuspend/resumeを自動的に処理します。`<Suspense>`は初回レンダーのみを担当する`<Loading>`に置き換えられ、更新は`isPending()`でバックグラウンド追跡されるため、再検証のたびにUIがスピナーに戻ることはありません。`action()`や`createOptimisticStore`といった楽観的プリミティブがコアに組み込まれ、Oxcベースの Rustコンパイラによりビルドが従来比20〜350倍高速化されました。
  - コード例:
```js
    // Solid 1.x — resourceで特殊処理
    const [data] = createResource(() => fetchUser(userId()));

    // Solid 2.0 — <Loading>境界内でPromiseをそのまま
    const data = createMemo(() => fetchUser(userId()));
```
  - 実務への適用: データの多い画面で再検証が発生しても、以前のコンテンツが画面に残るため、値を読み取る箇所でのみブロッキングされます。個々のデータが準備でき次第UIが更新される体験を作る際に、特に強力です。
  - 注意事項: まだRC段階のため、stableになるまでAPIが変わる可能性があります。また、`await`境界の後でシグナルを読み取ると追跡が途切れるため、**先にtrackしてからawaitする**という順序を守る必要があります。
- **[The Git War of 2026](https://github.blog/news-insights/company-news/the-august-17-outage-and-the-work-ahead/)** (出典: *Bytes #514*)
  - 背景: GitHubは現在、月間30億件のコミットを処理し、1億3千万件のPRをマージしていますが、この負荷によりシステムが限界に達しました。最近の8時間障害の間に3つのチームが同時に競合製品をリリースし、「Git War」が始まりました。
  - 主な機能 (競合アーキテクチャ):
    - **Cursor Origin** — GitHubのアーキテクトを迎えて作られた新しいGitホスティングアーキテクチャで、より高速で安定したものを目指しています。コードレビューUIはありますが、CI/CDはまだ自前で接続する必要があります。
    - **Pierre Computer Co.** — こちらも元GitHub出身チームが作ったAPI-only方式のGitストレージで、すでにLovableとBoltが使用中です。
    - **Cloudflare Artifacts** — 「Gitを喋るバージョンストレージ」で、事実上「Cloudflareの上にGitHubをセルフホスト」する概念です。バージョンストレージ、パイプライン、イベント、CIといったビルディングブロックを提供します。
  - 実務への適用: エージェントが大量のコードを生成する時代に、急増するコミット・PRを支えるGitインフラを模索するチームに、新しい選択肢が開かれました。
  - 注意事項: 3つの製品はいずれも、現在の形ではGitHubの完全な代替とはなりません。今のところは、負荷を分散して支える補完的な存在に近いといえます。

## 2. 🛠️ ツール & ライブラリ
- **[MicroLighter](https://daverupert.com/2026/08/microlighter/)** (出典: *Bytes #513*)
  + 概要: Dave Rupertが作った、依存関係のないクライアントサイド構文ハイライターで、CSS Custom Highlight APIを使用します。トークンごとに`<span>`を注入するのではなく、テキスト範囲を`CSS.highlights`に登録する方式のため、DOMがきれいに保たれます。
  + 使い方:
```js
    import { highlightAll } from "microlighter";
    import "microlighter/themes/github.css";
    await highlightAll();
    // <pre><code class="language-javascript">const answer = 42;</code></pre>
```
  + 実践チップ: コードのないページではスクリプトを遅延読み込みすることで、不要なコストを削減できます。ただし`::highlight()`疑似要素はitalic、bold、フォント変更をサポートしないという制限があるため、そうした機能が必要な場合はweb componentバンドルを併用すると良いでしょう。

## ✍️ おわりに

今週のニュースをまとめていると、フレームワークの技術的な優秀さと「エージェントがどれだけうまく扱えるか」が、次第に別の軸へと分かれつつあるという印象を受けます。CursorがSolidを離れた理由が、パフォーマンスや表現力ではなく「エージェントがReactの方が予測可能なコードを書く」ことだったという点は、じっくり考えてみる価値があります。そして、まさにその週にSolid 2.0がasyncの複雑さをフレームワーク側で吸収し、「エージェントが台無しにする余地を減らす」という方向で応じたことは、今後の競争構図を象徴的に示しています。

GitHub障害が引き金となったGitインフラ競争も、結局は同じ流れの延長線として読み取れます。人間のスピードではなくエージェントのスピードでコードが生み出される中で、私たちが当然のものとしてきたインフラの前提が、再び試練にさらされています。次々と登場するメジャーRCの中で、各ツールが「AI時代のワークフロー」にどう自らを適応させていくかを見守ることは、当分の間、最も興味深い観戦ポイントになりそうです。
