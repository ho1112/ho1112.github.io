## 🔥 이번 주 핵심 테마
이번 주는 "플랫폼이 흡수하는 것들"이 키워드였습니다. 아이콘 시스템, 숫자 정렬, 반응형 iframe, SVG 색상 주입처럼 예전에는 라이브러리나 JS 해킹이 맡던 일을 CSS와 HTML이 직접 해결하는 사례가 이어졌습니다. 런타임 쪽에서는 Deno가 Cloudflare에 합류하고 Bun이 타입 체커를 내장하는 등 지형 변화가 컸습니다. Node.js는 WebSocket 벤치마크에서 Bun과 Deno를 앞서는 결과를 내놓았습니다. 보안 측면에서는 Next.js 긴급 패치 예고, Handlebars와 Express의 취약점 수정이 겹쳤습니다.

## 1. 🔍 심층 분석
- **[The Best Way to Use Icons in Web UIs](https://lea.verou.me/blog/2026/icons/)** (출처: *Frontend Focus #762*)
   - 배경: 아이콘은 보통 인라인 SVG나 컴포넌트 추상화로 넣는데, 어떤 아이콘을 쓸지가 마크업에 박혀 상태별 교체나 일관성 관리가 어렵습니다. 아이콘 폰트는 CSS로 아이콘을 다뤘지만 용량, 접근성, 폰트 로딩 실패 문제가 있었습니다. 저자는 아이콘을 디자인 토큰으로 보고 CSS만으로 삽입하고 교체하는 방식을 제안합니다.
   - 핵심 기능: 아이콘을 `--icon-trash` 같은 CSS 변수(`<image>` 값)로 정의하고, `--icon`, `--icon-start`, `--icon-end` 속성으로 의사 요소에 삽입합니다. 의사 요소를 1em 사각형으로 만들고 `currentColor` 배경에 `mask`로 아이콘 모양을 입히며, 스타일 쿼리와 `@property`로 아이콘이 지정된 요소에만 적용합니다.
   - 코드 예제:
     ```css
     button.delete { --icon: var(--icon-trash); }

     @container style(--icon-start) {
       ::before { mask: var(--icon-start) no-repeat center / contain; }
     }
     ```
   - 실무 적용: `:hover`, 다크 모드, 인쇄 미디어 쿼리, 쓰기 방향에 따라 마크업 수정 없이 아이콘을 바꿀 수 있고, `details::marker` 같은 의사 요소에도 아이콘을 줄 수 있습니다. 직접 적용해 볼 수 있도록 `@nudeui/icons` 패키지로도 공개되었습니다.
   - 주의사항: 마스크 방식이라 단색 아이콘만 지원하며, 의사 요소 전체가 마스킹되어 별도 배경과 테두리는 줄 수 없습니다. 스타일 쿼리는 전 세계 브라우저의 약 93%에서 지원되고, Safari에는 WebKit 버그 #301609, #320220, #325900 때문에 우회 코드가 필요합니다. 상대 URL은 아이콘이 정의된 파일이 아니라 사용하는 CSS 기준으로 해석됩니다.
- **[Recursion is DEAD and HTML Killed It](https://daverupert.com/2026/10/html-recursion/)** (출처: *Frontend Focus #762*)
   - 배경: 중첩 댓글 같은 트리형 데이터는 서버에서 전체 트리를 먼저 조립한 뒤 재귀 렌더링해야 해서, 트리가 완성될 때까지 사용자가 기다립니다.
   - 핵심 기능: Chromium에서 시험 중인 Declarative Partial Updates는 `<?marker>` 자리 표시자를 두고, 나중에 도착한 `<template for="">`의 내용을 해당 위치에 자동으로 채웁니다. 서버 연결을 닫지 않고 HTML을 계속 흘려보내면 브라우저가 알아서 조립하므로, 서버에서 트리를 만들 필요 없이 게시글 단위로 곧바로 전송할 수 있습니다.
   - 코드 예제:
     ```html
     <main id="main">
       <?marker name="post-abc123" ?>
     </main>
     <template for="post-abc123"><div class="post">…</div></template>
     ```
   - 실무 적용: 중요한 콘텐츠를 먼저 보여주고 폴드 아래 콘텐츠는 늦게 와도 되는 경우에 적합합니다. 대댓글이 있는 게시글, 리뷰어 프로필이 붙는 상품 리뷰, PR 댓글 스레드가 예시로 나옵니다. LLM 챗봇의 스트리밍 응답에도 쓸 수 있다고 합니다.
   - 주의사항: Chromium 전용이며 FOUC와 LCP 관련 문제는 따로 관리해야 합니다. `<?marker>`는 한 번 채워지면 소모되므로 이어 붙이려면 같은 이름의 마커를 다시 넣어야 합니다. 게시글이 1만 개를 넘으면 브라우저에 부담이 되어 "더 보기" 버튼이 여전히 필요합니다.

## 2. 🛠️ 툴 & 라이브러리
- **[H3 v2: The UnJS HTTP Framework Rebuilt on Web Standards](https://h3.dev/blog/v2)** (출처: *JavaScript Weekly #806*)
  + 개요: Nitro와 Nuxt 서버 레이어의 기반인 미니멀 HTTP 프레임워크가 `Request`, `Response`, `URL`, `Headers` 표준 위로 전면 재작성되어 v2 stable이 되었습니다. 같은 앱이 Node, Bun, Deno, Workers, 브라우저에서 동작하고, URLPattern 유사 라우팅과 `(event, next)` 미들웨어를 지원합니다.
  + 사용법:
    ```js
    import { H3, serve } from "h3";

    const app = new H3().get("/", () => "⚡️ Tadaa!");

    serve(app, { port: 3000 });
    ```
  + 실전 팁: 새 `h3/rules`의 `routeRules`로 리다이렉트, 헤더, CORS, 캐시를 라우트 그룹 단위로 설정할 수 있습니다. v1 유틸리티 대부분이 그대로 동작하고, Node.js 환경에서는 `>= 20.19`가 필요합니다. 업그레이드 시 [Migration guide](https://h3.dev/migration)를 참고하면 됩니다.
- **[Shaders: 190+ WebGPU Effect Components, Now Open Source](https://shaders.com/updates/shaders-is-open-source)** (출처: *JavaScript Weekly #806*)
  + 개요: 물결, 글로우, ASCII 변환 같은 효과를 셰이더 코드가 아니라 컴포넌트로 조합하는 도구로, React, Vue, Svelte, Solid, 순수 JS를 지원합니다. 렌더링 엔진, 프레임워크 바인딩, 컴포넌트가 모두 MIT 라이선스로 공개되었습니다.
  + 실전 팁: 개인과 상업 프로젝트 모두 별도 라이선스 없이 쓸 수 있고, 디자인 에디터의 코드 내보내기도 무료입니다. 직접 컴포넌트를 만드는 `defineShader`는 실험적 기능입니다. Pro 구독은 1,000개 이상의 셰이더 등 기존 혜택을 유지합니다.

## 3. 📝 추천 아티클 & 팁
- **[Better Dashboard Figures](https://www.carmenansio.com/articles/opentype-features-css/)** (출처: *Smashing Newsletter #580*)
  ![Why Your Numbers Look Wrong](https://mcusercontent.com/16b832d9ad4b28edf261f34df/images/17c3cbdf-334f-6110-d98c-c45cfdef9871.png)
  + 핵심 인사이트: 대시보드 숫자가 어긋나 보이는 이유는 폰트의 기본 숫자가 비례폭이라 값이 갱신될 때 자릿수 폭이 달라지기 때문입니다. `tabular-nums`로 모든 숫자의 폭을 고정하면 열이 정렬되고 실시간 값의 흔들림이 사라집니다. 본문 속 숫자는 `oldstyle-nums`, 분수는 `diagonal-fractions`, 라벨은 진짜 `small-caps`를 쓰면 됩니다.
  + 코드 예시:
    ```css
    .amount { font-variant-numeric: tabular-nums; }
    .note   { font-variant-numeric: oldstyle-nums; }
    .qty    { font-variant-numeric: diagonal-fractions; }
    .head   { font-variant-caps: small-caps; }
    ```
  + 왜 유익한가: 네 줄의 CSS로 금융형 UI의 신뢰감을 바꿀 수 있고 Chrome 52, Firefox 34, Safari 9.1부터 지원되어 도입 부담이 없습니다. 다만 Google Fonts의 가변 폰트 빌드는 이 기능의 글리프를 제거한 경우가 많아, 효과가 없으면 폰트를 셀프 호스팅해야 한다는 함정도 짚어줍니다.
- **[Filling In The Last Row](https://twilson.net/writing/filling-responsive-grid)** (출처: *Smashing Newsletter #580*)
  ![Filling In The Last Row Of A Responsive Grid](https://mcusercontent.com/16b832d9ad4b28edf261f34df/images/131a6e24-9057-3138-c9ba-5735f355534a.png)
  + 핵심 인사이트: `1px` gap에 컨테이너 배경색을 테두리 색으로 쓰는 그리드 구분선 트릭은 마지막 행이 비면 틈이 드러납니다. 채워야 할 빈 셀 수는 `ceil(items / cols) * cols - items`로 계산하고, 반응형에서는 복잡한 계산 대신 브레이크포인트마다 별도의 필러 셀 묶음을 두고 `hidden md:block` 같은 클래스로 전환하는 방식이 가장 단순했다고 합니다.
  + 코드 예시:
    ```jsx
    {[...Array(Math.ceil(items / cols) * cols - items)].map((_, i) => (
      <div key={i} className="..." />
    ))}
    ```
  + 왜 유익한가: 요소 수는 약간 늘지만 커스텀 CSS 없이 이해하기 쉬운 해법입니다. gap decorations(`row-rule`, `column-rule`)가 지원되면 필요 없어지는 임시 방편이라는 점도 명확히 밝힙니다.
- **[Lazy Loading Images and Media: How Far Ahead Browsers Fetch](https://calibreapp.com/blog/native-lazy-loading)** (출처: *Frontend Focus #762*)
  + 핵심 인사이트: Chrome 페이지 로드의 26%만 `loading="lazy"` 이미지를 쓰는데, 17%의 페이지는 LCP 이미지를 lazy로 걸어 오히려 느려집니다. 지연 로딩 시작 거리는 브라우저마다 다릅니다. Chrome은 4G 기준 이미지 1,250px, Firefox는 600px, Safari는 한 뷰포트이며, `<video>`와 `<audio>`의 lazy는 Chrome 150+에서만 지원됩니다.
  + 코드 예시:
    ```html
    <img src="my-image.avif" loading="lazy" />
    <video src="showreel.mp4" loading="lazy" />
    ```
  + 왜 유익한가: 첫 화면 이미지는 eager로 두고 LCP 이미지에는 `fetchpriority="high"`, 폴드 아래만 lazy로 두는 규칙과 `width`/`height` 지정(CLS 방지)을 실측 수치와 함께 제시합니다. 프레임워크가 SSR 시 이미지에 preload를 붙이는 경우가 있으니 서버가 렌더링한 실제 HTML을 점검하라는 조언도 실용적입니다.

## ✍️ 마치며
이번 주 소식을 읽으며 가장 인상 깊었던 점은 아이콘, 숫자 정렬, iframe 높이처럼 오래 라이브러리와 우회 코드에 맡겨 온 문제가 플랫폼 기능으로 하나씩 돌아오고 있다는 것입니다. 다만 Lea Verou의 글이 보여주듯 Safari 버그 우회 같은 현실적인 비용이 남아 있어, 어디까지를 점진적 향상으로 받아들일지 팀 단위의 기준이 필요해 보입니다. 런타임 쪽에서는 Deno의 방향 전환과 Bun의 `bun check`, Node의 벤치마크 반격이 한 주에 겹치면서 선택지의 무게중심이 다시 움직이는 느낌입니다. 한편 Next.js 긴급 패치 예고와 Handlebars, Express의 취약점 수정은 의존성 업데이트를 미루지 않는 습관이 여전히 가장 싼 보안 대책임을 상기시킵니다.
