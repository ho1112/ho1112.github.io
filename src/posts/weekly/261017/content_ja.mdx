## 🔥 今週の主要テーマ
今週は「プラットフォームが取り込むもの」がキーワードでした。アイコンシステム、数字の桁揃え、レスポンシブiframe、SVGへの色の注入など、これまでライブラリやJSのハックが担っていたことを、CSSとHTMLが直接解決する事例が続きました。ランタイム側ではDenoがCloudflareに合流し、Bunが型チェッカーを内蔵するなど、勢力図の変化が大きい週でした。Node.jsはWebSocketベンチマークでBunとDenoを上回る結果を出しています。セキュリティ面では、Next.jsの緊急パッチ予告、HandlebarsとExpressの脆弱性修正が重なりました。

## 1. 🔍 深掘り
- **[The Best Way to Use Icons in Web UIs](https://lea.verou.me/blog/2026/icons/)** (出典: *Frontend Focus #762*)
   - 背景: アイコンは通常、インラインSVGやコンポーネントの抽象化で埋め込みますが、どのアイコンを使うかがマークアップに固定されてしまい、状態ごとの差し替えや一貫性の管理が難しくなります。アイコンフォントはCSSでアイコンを扱えましたが、容量、アクセシビリティ、フォントの読み込み失敗という問題がありました。著者はアイコンをデザイントークンと捉え、CSSだけで挿入・差し替えを行う方法を提案しています。
   - 主な機能: アイコンを `--icon-trash` のようなCSS変数(`<image>` 値)として定義し、`--icon`、`--icon-start`、`--icon-end` プロパティで擬似要素に挿入します。擬似要素を1emの正方形にし、`currentColor` の背景に `mask` でアイコンの形を適用します。スタイルクエリと `@property` により、アイコンが指定された要素にのみ適用されます。
   - コード例:
```css
     button.delete { --icon: var(--icon-trash); }

     @container style(--icon-start) {
       ::before { mask: var(--icon-start) no-repeat center / contain; }
     }
```
   - 実務への応用: `:hover`、ダークモード、印刷用メディアクエリ、書字方向に応じて、マークアップを変更せずにアイコンを切り替えられ、`details::marker` のような擬似要素にもアイコンを指定できます。すぐに試せるよう、`@nudeui/icons` パッケージとしても公開されました。
   - 注意事項: マスク方式のため単色アイコンのみ対応しており、擬似要素全体がマスクされるため、別途背景や枠線を付けることはできません。スタイルクエリは全世界のブラウザの約93%で対応しており、SafariではWebKitのバグ #301609、#320220、#325900 の影響で回避用のコードが必要です。相対URLは、アイコンが定義されたファイルではなく、使用するCSSを基準に解決されます。
- **[Recursion is DEAD and HTML Killed It](https://daverupert.com/2026/10/html-recursion/)** (出典: *Frontend Focus #762*)
   - 背景: ネストされたコメントのようなツリー型データは、サーバー側でツリー全体を組み立ててから再帰的にレンダリングする必要があり、ツリーが完成するまでユーザーは待たされます。
   - 主な機能: Chromiumで試験中のDeclarative Partial Updatesは、`<?marker>` というプレースホルダーを置いておくと、後から届いた `<template for="">` の内容がその位置に自動的に埋め込まれます。サーバー接続を閉じずにHTMLを流し続ければブラウザが自動で組み立ててくれるため、サーバー側でツリーを作らなくても、投稿単位ですぐに送信できます。
   - コード例:
```html
     <main id="main">
       <?marker name="post-abc123" ?>
     </main>
     <template for="post-abc123"><div class="post">…</div></template>
```
   - 実務への応用: 重要なコンテンツを先に見せ、ファーストビューより下のコンテンツは遅れて届いてもよい場合に向いています。返信付きの投稿、レビュアープロフィール付きの商品レビュー、PRのコメントスレッドが例として挙げられています。LLMチャットボットのストリーミング応答にも使えるそうです。
   - 注意事項: Chromium専用で、FOUCやLCPに関する問題は別途管理する必要があります。`<?marker>` は一度埋まると消費されるため、続けて追加したい場合は同じ名前のマーカーを再度入れる必要があります。投稿が1万件を超えるとブラウザに負荷がかかるため、「もっと見る」ボタンは依然として必要です。

## 2. 🛠️ ツール & ライブラリ
- **[H3 v2: The UnJS HTTP Framework Rebuilt on Web Standards](https://h3.dev/blog/v2)** (出典: *JavaScript Weekly #806*)
  + 概要: NitroとNuxtのサーバーレイヤーの基盤となるミニマルなHTTPフレームワークが、`Request`、`Response`、`URL`、`Headers` の標準仕様をベースに全面的に書き直され、v2 stableとなりました。同じアプリがNode、Bun、Deno、Workers、ブラウザで動作し、URLPatternに似たルーティングと `(event, next)` ミドルウェアをサポートします。
  + 使い方:
```js
    import { H3, serve } from "h3";

    const app = new H3().get("/", () => "⚡️ Tadaa!");

    serve(app, { port: 3000 });
```
  + 実践チップ: 新しい `h3/rules` の `routeRules` で、リダイレクト、ヘッダー、CORS、キャッシュをルートグループ単位で設定できます。v1のユーティリティの大半はそのまま動作し、Node.js環境では `>= 20.19` が必要です。アップグレード時は[Migration guide](https://h3.dev/migration)を参照してください。
- **[Shaders: 190+ WebGPU Effect Components, Now Open Source](https://shaders.com/updates/shaders-is-open-source)** (出典: *JavaScript Weekly #806*)
  + 概要: 波紋、グロー、ASCII変換といったエフェクトを、シェーダーコードではなくコンポーネントとして組み合わせられるツールで、React、Vue、Svelte、Solid、素のJSに対応しています。レンダリングエンジン、フレームワークバインディング、コンポーネントのすべてがMITライセンスで公開されました。
  + 実践チップ: 個人・商用プロジェクトのどちらでも別途ライセンスなしで利用でき、デザインエディタのコードエクスポートも無料です。独自のコンポーネントを作成する `defineShader` は実験的な機能です。Proサブスクリプションは、1,000個以上のシェーダーなど従来の特典を維持します。

## 3. 📝 おすすめ記事 & チップ
- **[Better Dashboard Figures](https://www.carmenansio.com/articles/opentype-features-css/)** (出典: *Smashing Newsletter #580*)
  ![Why Your Numbers Look Wrong](https://mcusercontent.com/16b832d9ad4b28edf261f34df/images/17c3cbdf-334f-6110-d98c-c45cfdef9871.png)
  + 主要なインサイト: ダッシュボードの数字がずれて見える理由は、フォントのデフォルトの数字がプロポーショナル幅であるため、値が更新されるたびに桁の幅が変わってしまうからです。`tabular-nums` ですべての数字の幅を固定すれば、列が揃い、リアルタイムの値の揺れもなくなります。本文中の数字には `oldstyle-nums`、分数には `diagonal-fractions`、ラベルには本物の `small-caps` を使えます。
  + コード例:
```css
    .amount { font-variant-numeric: tabular-nums; }
    .note   { font-variant-numeric: oldstyle-nums; }
    .qty    { font-variant-numeric: diagonal-fractions; }
    .head   { font-variant-caps: small-caps; }
```
  + なぜ役立つのか: わずか4行のCSSで金融系UIの信頼感を変えられ、Chrome 52、Firefox 34、Safari 9.1以降で対応しているため、導入の負担もありません。ただし、Google Fontsの可変フォントビルドではこの機能のグリフが削除されていることが多く、効果が出ない場合はフォントをセルフホストする必要があるという落とし穴も指摘しています。
- **[Filling In The Last Row](https://twilson.net/writing/filling-responsive-grid)** (出典: *Smashing Newsletter #580*)
  ![Filling In The Last Row Of A Responsive Grid](https://mcusercontent.com/16b832d9ad4b28edf261f34df/images/131a6e24-9057-3138-c9ba-5735f355534a.png)
  + 主要なインサイト: `1px` のgapにコンテナの背景色を枠線の色として使うグリッド区切り線のトリックは、最後の行が空いていると隙間が見えてしまいます。埋めるべき空セルの数は `ceil(items / cols) * cols - items` で計算できます。レスポンシブ対応では、複雑な計算をする代わりに、ブレークポイントごとに別々のフィラーセルのまとまりを用意し、`hidden md:block` のようなクラスで切り替える方法が最もシンプルだったとのことです。
  + コード例:
```jsx
    {[...Array(Math.ceil(items / cols) * cols - items)].map((_, i) => (
      <div key={i} className="..." />
    ))}
```
  + なぜ役立つのか: 要素数は少し増えますが、カスタムCSSなしで理解しやすい解決策です。gap decorations(`row-rule`、`column-rule`)がサポートされれば不要になる暫定的な対処法であることも、はっきり述べられています。
- **[Lazy Loading Images and Media: How Far Ahead Browsers Fetch](https://calibreapp.com/blog/native-lazy-loading)** (出典: *Frontend Focus #762*)
  + 主要なインサイト: Chromeのページロードのうち `loading="lazy"` の画像を使っているのは26%だけで、17%のページはLCP画像にlazyを指定してしまい、かえって遅くなっています。遅延読み込みを開始する距離はブラウザごとに異なり、Chromeは4G基準で画像1,250px、Firefoxは600px、Safariは1ビューポート分です。`<video>` と `<audio>` のlazyはChrome 150以降でのみサポートされています。
  + コード例:
```html
    <img src="my-image.avif" loading="lazy" />
    <video src="showreel.mp4" loading="lazy" />
```
  + なぜ役立つのか: ファーストビューの画像はeagerのままにし、LCP画像には `fetchpriority="high"` を指定し、ファーストビューより下の画像だけをlazyにするというルールと、`width`/`height` の指定(CLS防止)を、実測値とともに示しています。フレームワークがSSR時に画像へpreloadを付ける場合があるため、サーバーがレンダリングした実際のHTMLを確認するようにという助言も実用的です。

## ✍️ おわりに
今週のニュースを読んで最も印象的だったのは、アイコン、数字の桁揃え、iframeの高さなど、長らくライブラリや回避コードに任せてきた問題が、プラットフォームの機能として一つずつ戻ってきているということです。ただし、Lea Verouの記事が示すように、Safariのバグ回避といった現実的なコストが残っているため、どこまでをプログレッシブエンハンスメントとして受け入れるか、チーム単位での基準が必要に思えます。ランタイム側では、Denoの方向転換、Bunの `bun check`、Nodeのベンチマークでの反撃が1週間に重なり、選択肢の重心が再び動いている感覚があります。一方で、Next.jsの緊急パッチ予告やHandlebars、Expressの脆弱性修正は、依存関係のアップデートを先送りしない習慣が、今なお最も安上がりなセキュリティ対策であることを思い出させてくれます。
