## 🔥 今週の主要テーマ
- AIエージェントがコードを書く時代に、フレームワークの選定基準を問い直すベンチマークが話題になりました。コストの差は不明瞭でしたが、ブラウザに配信されるJavaScriptの量には明確な差が表れました。一方、npmパッケージのクールダウン、サードパーティスクリプトのハイジャック、GitHub Actionsのpull_request_targetブロックなど、サプライチェーンセキュリティ関連の話題が相次ぎ、DiscordのRust移行やParcel 3のRust書き直しのように、ネイティブ言語へ重心が移る流れも目を引きました。Safariはサイトに代わってダークモードを適用してくれる機能をベータで公開しました。

## 1. 🔍 深掘り
- **[The AI Cost of JavaScript Frameworks](https://nolanlawson.com/2026/10/28/the-ai-cost-of-javascript-frameworks/)** (出典: *JavaScript Weekly #809*)
  ![The AI Cost of JavaScript Frameworks](https://res.cloudinary.com/cpress/image/upload/w_1280,e_sharpen:60,q_auto/dhcgdjewfv50joacutkm.jpg)
   - 背景: 「特定のフレームワークの方がエージェントに向いている」という主張を検証するため、Nolan LawsonがClaudeに同じアプリを12のJSスタックでそれぞれ5回ずつ作らせました。
   - 主要機能: 実行ごとのコストのばらつきが大きく、Gautam Parabは、観測されたコストの範囲はほとんどのフレームワークの組み合わせで重なるか接していると[分析](https://gautamparab.com/writing/sixty-of-sixty-six-ranges-overlap/)しました。一方、ブラウザに送信されたJavaScriptの中央値には明確な差がありました。Astro 0KB、Hono+htmx 18K、SvelteKit 36K、React Router・TanStack Start・Next.jsは115〜142Kでした。
   - 実務への適用: コードを自分で書かない「hands-free」開発なら、自分でコードを書いていた時代に選んだスタックをなぜそのまま維持するのか、あらためて問い直すことができます。[ベンチマークリポジトリ](https://github.com/nolanlawson/agent-framework-benchmark)が公開されているので、自分で実行してみることもできます。
   - 注意事項: コストは実行ごとのばらつきが大きいため、1〜2回の測定値でフレームワークの優劣を決めるのは難しいです。
- **[Safari Introduces Adaptive Dark Mode](https://webkit.org/blog/18541/introducing-adaptive-dark-mode/)** (出典: *Frontend Focus #765*)
  ![Safari Introduces Adaptive Dark Mode](https://webkit.org/wp-content/uploads/Demo-of-Adaptive-Dark-Mode_light.png)
   - 背景: ページロードの約40%がダークモードを使うユーザーによるものですが、ダークモードに直接対応しているページロードは約10%にとどまります。
   - 主要機能: Safari 27.3ベータに追加された機能で、ライトなサイトを自動的にダークサイトのように見えるよう変換します。
   - 注意事項: ユーザーがオンにしないと動作しないopt-in方式で、まだベータ段階です。

## 2. 🛠️ ツール & ライブラリ
- **[Parcel 3 Alpha: A Rust Rewrite with React Compiler, Tailwind and RSC](https://v3.parceljs.org/blog/v3-alpha/)** (出典: *React Status #496*)
  + 概要: ParcelのコアがNode依存のないRustバイナリに置き換えられ、チームはコールドビルドがv2より最大100倍速くなったと発表しています。React Compiler(opt-in)、Tailwind、MDXが組み込まれ、RSCサポートはベータです。
  + 実践チップ: React Compilerはopt-in、RSCはベータなので、導入時にどの機能がまだ実験段階なのかを区別して確認する必要があります。
- **[x18n: Lint and Maintain i18n Files for Any Framework](https://x18n.dev/)** (出典: *JavaScript Weekly #809*)
  + 概要: Anthony Fuが作った[i18n-ally](https://github.com/lokalise/i18n-ally)の後継ツールで、ロケールファイルと翻訳呼び出しをスキャンし、欠落・未使用・壊れたキーを報告します。
  + 実践チップ: tsc --noEmitが型エラーを教えてくれるように翻訳キーの問題を教えてくれる方式なので、型チェックと同じ感覚でチェックの段階に組み込んで使えます。

## 3. 📝 おすすめ記事 & チップ
- **[Design Systems Should Be Fast by Default](https://denodell.com/blog/design-systems-should-be-fast-by-default)** (出典: *Frontend Focus #765*)

  + 要約: DiscordのCTOがGPUIベースのRustデスクトップクライアントを[公開](https://x.com/svishnevskiy/status/2118081920194203799)し、メモリ使用量は290MBでした。モバイルはデスクトップと共有するRustコードの上にネイティブUIを維持します。直前に公開されたDiscordのReact Native運用の話は[動画](https://www.youtube.com/watch?v=NYOM5ujWI9Y)で見られます。
- **[Third-Party Scripts](https://blog.report-uri.com/polymarkets-csp-allowed-every-part-of-the-2-6-million-crypto-theft/)** (出典: *Frontend Focus #765*)
  + 要約: 10月29日、Polymarketでパフォーマンスモニタリングスクリプトがウォレット窃取スクリプトにすり替えられました。スクリプトのURLはそのままで中身だけが変わったため、CSPを通過しました。対策として[Subresource Integrity](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Subresource_Integrity)の適用やサードパーティリソースのセルフホスティングなどが紹介されています。
- **[Update to Next.js 16.4.5 or 15.5.29](https://nextjs.org/blog/november-2026-security-release)** (出典: *React Status #496*)
  + 要約: 11月のセキュリティリリースで7件のadvisoryが修正され、そのほとんどがCache Components関連のバグです。
- **[GitHub Actions Will Block pull_request_target by Default in Public Repos](https://github.blog/changelog/2026-11-02-pull_request_target-blocked-by-default-december-2)** (出典: *JavaScript Weekly #809*)
  + 要約: 12月2日から、イベントポリシーが明示的に許可しない限り、パブリックリポジトリでpull_request_targetがデフォルトでブロックされます。11月9日と16日にbrownoutが予定されています。
- **[Cloudflare Workers Now Supports the Temporal API Natively](https://developers.cloudflare.com/workers/configuration/compatibility-flags/#enable-the-temporal-api)** (出典: *JavaScript Weekly #809*)
  + 要約: temporal互換性フラグの背後でTemporal APIをネイティブサポートしており、12月1日からはデフォルトで有効になります。

## ✍️ おわりに
エージェントがコードを書く環境では、フレームワークを選ぶ基準も変わるべきだという点が、今週もっとも印象的でした。コストの差は不明瞭でしたが、ユーザーに配信されるJavaScriptの量は数字ではっきりと分かれ、結局のところ成果物の重さが選択基準になりうると感じました。また、パッケージのクールダウン、SRI、pull_request_targetのデフォルトブロックのように、サプライチェーンセキュリティへの対応が設定とポリシーの領域に降りてきており、個別のツールよりチームのデフォルト設定を点検することが重要になりました。DiscordとParcelがRustへ向かう流れまで重ねて見ると、フロントエンド開発者が扱う境界が広がり続けていることを実感します。
